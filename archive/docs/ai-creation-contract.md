# 生活有谱智能创建契约

> 项目代号：`life-book` · 版本：v1.1 · 更新日期：2026-07-26 · 状态：智能能力基线
>
> 权威范围：智能创建会话、供应商无关草稿语义、字段来源、校验、失败、数据边界和阶段扩展
>
> 不负责：机器字段唯一拼写、网络 HTTP 细节、提示词全文和模型具体版本
>
> 依赖文档：[产品需求基线](product-features.md)、[领域模型](domain-model.md)、[时间与重复规则](time-and-recurrence.md)、[业务规则](business-rules.md)、[数据生命周期](data-lifecycle.md)

机器结构由 [`specs/ai/record-draft.schema.json`](../specs/ai/record-draft.schema.json) 唯一定义；本文解释结构的产品与领域语义。模型只负责理解和整理，程序负责校验，用户负责最终确认。

## 1. 不可突破的边界

### AI-001：智能创建是输入方式

- 智能创建位于全局加号，不是独立聊天产品。
- 手动创建五种记录始终可用，不因额度、网络、地区或模型故障关闭。
- 模型输出只能成为草稿、追问或无法处理结果。
- 模型不拥有数据库连接、文件系统访问、通知调度、账号权限或领域命令执行能力。
- 未经用户确认，不能创建记录、改变库存、勾选清单、设置提醒、移动空间或删除数据。

### AI-002：P0 一次只处理一条记录

P0 一个会话只产生一条草稿：

- 一个明确意图：识别并生成草稿；
- 一个关键歧义：最多追问一轮、一个问题；
- 多个独立意图：返回 multiple_intents，用户选择一种类型转手动或只保留其中一条重新提交；
- 回答后仍歧义：转手动；
- 不支持的规则：说明限制并带入手动表单，不能近似保存。

P1 才支持多轮和多草稿。

### AI-003：字段来源必须可见

每个会改变结果的草稿字段标记来源：

| 来源 | 代码 | 含义 | 界面 |
| --- | --- | --- | --- |
| 用户明确提供 | `explicit` | 可以从本次输入或追问答案直接定位。 | 正常展示。 |
| 模型推断 | `inferred` | 根据语境推断但用户没有明确说。 | 标“根据描述推测”。 |
| 系统默认 | `default` | 来自产品固定默认或用户设置。 | 标“系统建议”。 |
| 用户在确认页修改 | `confirmed_edit` | 用户主动改变。 | 视为已确认，不再显示模型来源。 |

来源不是模型置信度。界面不展示容易造成虚假精确感的 0–1 分数。

### AI-004：不输出或保存推理过程

契约不得包含链式推理、隐藏提示词、内部安全规则或长篇模型解释。允许返回简短、可展示的 `warningCode` 和字段来源，不保存模型“为什么这样想”的自由文本。

## 2. P0 会话

### AI-010：创建会话状态

```text
idle
→ editing_input
→ consent_required（首次）
→ submitting
→ clarification_required → submitting_once
→ draft_ready → editing_draft → confirming → saved

任意在线阶段 → retryable_error / manual_fallback / cancelled
```

`saved` 之前没有正式记录 ID。会话只在当前进程内存存在；用户确认退出或进程终止后按 DATA-011 清理。

### AI-011：输入约束

- 去除首尾空白后 1–4,000 个 Unicode 码点；
- 允许换行和自然标点；
- 超长输入保留在输入框，提示缩短或转备忘手动表单，不静默截断后发送；
- P0 只接受文字，不上传附件、录音或图片；
- 用户可以在提交前选择一种手动类型，原文带入适用字段；
- 输入中的 URL、代码或指令一律作为用户内容，不被服务端执行或抓取。

### AI-012：首次数据说明

首次提交前说明：

> 本次文字会发送给智能服务进行整理。默认不会发送生活簿中的其他记录；确认前不会写入生活记录数据库。你也可以随时改用手动创建。

同时提供隐私详情链接，说明实际启用供应商、处理地区、可能的供应商留存和手动替代。确认按说明版本记录；地区、供应商数据用途或说明实质变化时重新确认。

### AI-013：参考上下文固定

首次提交时固定：

- `referenceInstant`；
- `referenceTimeZone`；
- `locale` 与地区格式；
- `weekStart`；
- 当前 App/草稿 Schema/时间规则版本；
- P0 允许能力矩阵。

追问答案和重试继续使用同一上下文，避免跨午夜把“明天”解释成不同日期。

### AI-014：取消与迟到响应

- 用户取消后立即标记会话 generation 失效；
- 迟到的网络响应只记录无内容的完成状态，不进入确认页；
- 重新提交生成新 requestId 和 generation，但沿用固定参考上下文，除非用户回到输入页主动“按现在重新理解”；
- 同一个 requestId 的网络重试必须幂等，不能重复扣额或生成两份业务会话结果。

## 3. 客户端到智能网关的语义请求

### AI-020：`ParseDraftRequest`

请求至少包含：

| 字段 | 语义 |
| --- | --- |
| `requestId` | 客户端生成的幂等请求 ID。 |
| `sessionId` | 当前内存会话的随机 ID，不跨进程长期追踪。 |
| `attempt` | 0 为首次，1 为唯一追问回答；P0 不接受更高值。 |
| `rawInput` | 本次原始文字。 |
| `clarification` | attempt=1 时包含 questionId 和用户回答。 |
| `referenceContext` | 固定时间、时区、语言、地区和周起始。 |
| `contractVersion` | 客户端支持的 DraftEnvelope Schema 版本。 |
| `capabilityProfile` | 当前阶段允许的类型、历法、重复规则、附件/关联等布尔能力。 |
| `clientBuild` | 兼容与灰度用粗粒度版本，不含设备指纹。 |

P0 请求不包含安装内其他记录、分类/标签列表、附件、联系人、位置、账号资料或历史会话。

### AI-021：Capability Profile

服务端不能仅根据最新产品能力生成字段；必须遵守客户端发送并由服务端校验的能力 Profile。例如 P0：

- 允许五种记录；
- 重要日期只允许公历；
- 只允许 P0 重复规则；
- 单草稿、单追问；
- 不允许记录关联、家庭空间、BYOK 字段、图片/语音来源；
- 附件不由文字模型生成；
- 分类/标签只允许输出用户明确提及或普通建议名称，不假设已有对象 ID。

服务端配置可以比客户端更严格，不能更宽松。

### AI-022：服务端上下文

网关可以添加但不得从用户数据库读取：

- 统一系统指令和字段定义；
- 当前支持的契约 Schema；
- 地区允许的供应商和模型别名；
- 产品固定默认值；
- 无内容的配额和风控信号。

服务端不得把其他用户输入、示例中的真实用户内容或客服数据拼入提示。

## 4. 统一返回封装

### AI-030：`DraftEnvelope` 结果

所有供应商必须转换成以下互斥业务状态之一：

| 状态 | 含义 | 客户端下一步 |
| --- | --- | --- |
| `draft` | 一条通过 Schema 初检的候选草稿。 | 程序业务校验后进入确认页。 |
| `clarification_required` | 缺一个会影响正确创建的关键值。 | P0 展示唯一问题。 |
| `unrecognized` | 无法确定五种类型或没有可保存信息。 | 选择手动类型，原文保留。 |
| `multiple_intents` | 输入包含多个独立记录意图。 | 展示检测到的类型摘要，选择一条手动处理。 |
| `unsupported` | 意图清楚但超出当前能力。 | 说明当前限制并提供最近手动路径。 |
| `content_refused` | 供应商或安全策略拒绝处理。 | 不推断内容，转手动。 |

配额、认证、限流、超时和服务故障是传输/服务错误，不伪装成上述模型业务状态。

### AI-031：通用封装字段

返回必须包含：

- `contractVersion`；
- `requestId`（原样关联请求）；
- `providerRequestIdHash` 或内部追踪 ID，不暴露供应商凭据；
- `result` 互斥联合；
- `promptVersion` 与 `adapterVersion`；
- `modelAlias`（内部稳定别名，普通确认页不必展示）；
- `fieldProvenance`；
- 受控 `warningCodes`；
- 无内容用量摘要，供额度显示。

不得向客户端返回供应商原始响应或隐藏推理。

### AI-032：追问结构

`clarification_required` 包含：

| 字段 | 规则 |
| --- | --- |
| `questionId` | 当前请求内唯一、不可解释为数据库 ID。 |
| `reasonCode` | `ambiguous_date/time/duration/quantity/unit/type/range/timezone` 等受控码。 |
| `promptKey` | 本地化文案键；可带安全参数，不接受任意 HTML。 |
| `answerType` | `date \| time \| number \| unit \| single_choice \| short_text`。 |
| `options` | 最多 5 个互斥选项，可空。 |
| `suggestedAnswer` | 只有安全默认时存在并标记 default。 |

问题必须只询问一个概念。`promptKey + params` 优先由客户端本地化；供应商生成的自由问题只能作后备并经过长度/内容清理。

### AI-033：警告码

至少支持：

- `used_default_time`；
- `inferred_title`；
- `inferred_low_stock_threshold`；
- `past_reminder_omitted`；
- `timezone_explicit`；
- `large_generated_checklist`；
- `sensitive_content_notice`；
- `provider_fallback_used`（只在详情/诊断显示）。

警告不代替字段来源或业务校验。

## 5. 通用草稿字段

### AI-040：`CommonDraft`

五种草稿共享：

| 字段 | 规则 |
| --- | --- |
| `recordType` | 五种稳定枚举之一。 |
| `title` | 必填，满足领域长度；推断标题必须标 inferred。 |
| `description` | 可选；不复制大段原文到标题和说明两处。 |
| `categoryName` | 可选字符串；P0 本地按规范化名称映射/新建，不能输出不存在的 categoryId。 |
| `tagNames` | 去重字符串，最多 20；P0 本地映射。 |
| `sensitivity` | 只有用户明确要求时可以为 sensitive；模型不得根据内容类型偷偷标记。 |
| `aiAccess` | sensitive 时默认 denied；确认页允许用户理解后改变。 |

模型不输出记录 ID、空间 ID、创建人、revision、归档/删除状态或系统通知 ID；这些由程序创建。

### AI-041：字段来源映射

`fieldProvenance` 使用 JSON Pointer 指向草稿字段。数组中的每个生成清单项目和每个提醒都必须有来源；父路径来源不能含糊覆盖具有不同来源的子字段。

`explicit` 字段可以附带输入码点范围以支持解释，但范围只在当前会话使用，不进入正式记录或日志。

### AI-042：默认值来源

固定默认只由程序或版本化产品配置提供，模型不能自称“系统默认”：

- 时区：referenceTimeZone；
- 周起始日：referenceContext.weekStart；
- 全天提醒时刻：用户设置或 09:00；
- 敏感：normal，除非用户明确；
- AI access：普通 allowed、敏感 denied；
- 提醒重复催促：关闭；
- 分类/标签：无，除非明确或作为清楚建议；
- 库存最低阈值：无，除非明确或被标 inferred 并由用户确认。

## 6. 五种草稿

### AI-050：重复事项草稿

包含：

- CommonDraft；
- `startDate`；
- `schedule`（全天、浮动本地时间或时区绑定时间；重复规则不允许 instant）；
- `recurrenceRule`；
- P0 最多一个主 `reminderPlanDraft`；
- `reminderPlanDraft` 只允许 `at_schedule` 或 `relative_to_schedule`；
- 可选 `followUpPolicyDraft` 属于该 `reminderPlanDraft`，只有用户明确要求连续提醒时生成，不能脱离提醒计划存在。

规则：

- “每周日晚上九点提醒我整理”同时表达业务计划和 at_schedule 提醒，不创建两个重复事项；
- “持续一个月”若自然月/30 天导致不同结束日且语境不能唯一确定，使用唯一追问；
- 不支持“每月最后一天”时返回 unsupported，不近似为 31 日；
- 必须用同一 REC-* 引擎预览未来 5 项后才能展示确认。

### AI-051：清单草稿

包含：

- CommonDraft；
- `purpose = general | shopping`；
- 可选分组数组；
- 项目数组：标题、可选说明、可选数量/单位、可选分组引用；
- 可选截止 ScheduleSpec；
- P0 最多一个提醒计划，只允许 `at_schedule` 或 `relative_to_schedule`。

规则：

- 生成旅行等清单项目属于模型建议，每个生成项目标 inferred；
- 用户明确列出的项目标 explicit；
- P0 最多 100 个模型生成项目，超过返回前截为 100 并使用 `large_generated_checklist`，确认页清楚说明；用户手动可继续添加至领域上限；
- 不生成完成状态、模板 ID、绝对排序 ID或已完成清单；
- “帮我做一个以后都能用的模板”在 P0 生成清单草稿并在确认后建议另存模板，不直接生成第六类对象。

### AI-052：备忘草稿

包含：

- CommonDraft；
- `body`；
- 0 个或多个 `absolute_schedule` 提醒计划。

规则：

- 标题和正文至少一项有内容；若输入主要是正文，模型可以建议短标题并标 inferred；
- 型号、联系方式和注意事项按用户原文保留，不自动改写关键字符；
- 提醒不会改变为重复事项；
- P0 不生成附件和记录关联。

### AI-053：重要日期草稿

包含：

- CommonDraft；
- `eventKind`；
- `calendarSystem`；
- `recurrenceMode`；
- `dateValue`；
- 可选 `startYear`；
- `counterDisplay`；
- 0 个或多个 `relative_to_schedule` 提醒计划；当天提醒用偏移 0 和明确本地时刻表达。

规则：

- P0 只允许 gregorian；用户明确农历时返回 unsupported 并提供手动备忘替代，不能把农历数字当公历；
- 生日/纪念日没有年份时 yearly 且 startYear 为空；
- 证件/保险/保修到期默认 once，除非用户明确每年；
- 事件种类、历法和重复方式分别校验；
- 多个提前提醒分别生成计划并按时间去重。

### AI-054：家庭物品草稿

包含：

- CommonDraft；
- `initialQuantity`；
- `unit`；
- 可选 `lowStockThreshold`；
- 可选 `storageLocation`；
- 可选期初备注。

规则：

- initialQuantity 必须明确或使用一次追问；不能默认猜 0 后隐藏。
- unit 对有数量的物品必须明确或追问；纯整数“两个行李箱”可以根据量词建议“个”并标 inferred。
- threshold 未明确时默认空；模型可以建议但必须标 inferred。确认 `lowStockThreshold` 即确认开启该物品的低库存判断与未来 `state_entered` 事件提醒，模型不另造 reminderPlanDraft。
- 草稿只含期初数量，不含 StockTransaction；用户确认后由领域层原子创建 opening 流水。
- 买入/使用语句若物品尚不存在，P0 只能创建新家庭物品及期初数量；不能查询并修改已有库存。

## 7. 确定性校验

### AI-060：校验流水线

```text
供应商响应
→ 解析 JSON
→ record-draft Schema 校验
→ Contract/Capability Profile 校验
→ 字段长度、枚举与数值校验
→ 时间/时区/重复规则校验和预览
→ 类型交叉字段校验
→ 分类标签规范化预检
→ 隐私与敏感规则
→ 生成可展示确认模型
```

任一步失败都不能进入保存命令。可以对同一供应商响应做一次纯程序修复（例如去除未知字段）；需要模型二次修复时视为一次供应商内部重试并记录，仍须完整校验。

### AI-061：禁止自动修复的错误

以下必须追问、unsupported 或转手动，不能猜：

- 不存在或互相冲突的日期；
- 多个可能时区；
- 负库存或无法确定数量/单位；
- 不支持的重复规则被近似成另一规则；
- 一次与每年重复冲突；
- 清单和备忘等多个独立意图被合并成一条；
- 模型填入当前阶段不开放字段；
- 未知枚举、额外记录类型或领域命令。

### AI-062：安全可修复项

程序可以在不改变含义时：

- 去除首尾空白；
- 去重标签、星期和提醒计划；
- 把全角数字规范化后保留显示；
- 按 Schema 删除完全未知、未使用字段并记录 adapter 警告；
- 将明确单位别名映射为用户可见标准形式，确认页仍显示；
- 按 referenceContext 填充确定的时区和周起始日，标 default。

### AI-063：服务端与客户端双重校验

- 智能网关在返回前校验，防止无效内容占用客户端流程；
- 客户端使用同一 Schema 和领域规则再次校验，不能信任服务端；
- 两端 JSON Schema 校验器必须启用 Draft 2020-12 `format` 断言，并继续执行真实日历、IANA 时区和跨字段确定性校验；
- 两端规则版本不兼容时返回 `client_upgrade_required`，不选择其中一端悄悄保存；
- 最终保存始终调用正常领域命令，与手动表单使用同一规则。

## 8. 确认与保存

### AI-070：确认页内容

SCR-103 必须展示：

- 记录类型和可切换到手动重建的入口；
- 五种类型的正常用户字段；
- 完整、可理解的日期、时区、重复预览和提醒时间；
- 初始库存、单位、阈值和变化结果；
- 每个 inferred/default 关键字段的来源标记；
- 警告、已错过提醒和当前权限/近似提醒状态；
- 修改、重新生成、取消和确认。

不得直接展示 JSON、模型别名、置信小数或隐藏推理。

### AI-071：用户编辑

- 用户编辑后该字段来源变为 confirmed_edit；
- 依赖字段重新校验，例如日期改变后提醒和预览重算；
- 编辑不自动再次调用模型，除非用户主动重新生成；
- 重新生成期间保留当前草稿，失败时可继续使用旧草稿；
- 切换记录类型进入对应手动表单，只携带可安全映射的原始输入和字段，不要求模型转换。

### AI-072：原子保存

确认时客户端构造正常领域命令：

- 再次读取当前时钟、权限和空间，但日期解析仍使用固定参考上下文中已确认的绝对/本地值；
- 再次校验 Schema、领域不变量和能力版本；
- 一次本地事务创建根记录、详情、分类标签关系、适用期初流水和提醒计划；
- 成功后才递增真实记录计数并进入 SCR-104；
- 保存失败保留确认模型并提供重试，不调用模型重新生成。

### AI-073：取消

取消不创建回收站条目、不扣除第二次保存额度、不留下提醒或库存流水。已经发生的模型用量可以计入服务额度，但界面应区分“本次已使用智能整理”和“记录尚未保存”。

## 9. 错误、重试和降级

### AI-080：错误分类

| 类别 | 示例 | 是否自动重试 | 用户路径 |
| --- | --- | :---: | --- |
| 网络暂时失败 | 断网、连接超时 | 客户端最多 1 次，带幂等键 | 重试 / 转手动 |
| 供应商暂时失败 | 429、5xx、超时 | 网关可换允许供应商 1 次 | 显示暂不可用 |
| 额度不足 | 安装/账号额度耗尽 | 否 | 显示额度状态，转手动 |
| 内容无法识别 | unrecognized | 否 | 选择手动类型 |
| 多意图 | multiple_intents | 否 | 选择一条处理 |
| 当前不支持 | unsupported | 否 | 说明限制，转手动 |
| Schema/校验失败 | 无效 JSON、字段冲突 | 网关内部最多 1 次 | 失败则转手动 |
| 客户端版本旧 | contract 不兼容 | 否 | 升级或手动 |
| 安全拒绝 | content_refused | 否 | 不解释内部规则，转手动 |

### AI-081：供应商回退

网关只在以下条件回退一次：

- 主供应商为暂时错误，不是输入/安全拒绝；
- 备用供应商在当前发行地区允许并出现在用户可访问的第三方说明中；
- 备用供应商满足同等或更严格数据处理配置；
- requestId 保持，provider attempt 单独编号；
- 两次结果都不记录完整内容。

若地区或同意范围不允许换供应商，直接降级手动。

### AI-082：输入不丢失

所有错误页保留：原始输入、固定参考上下文、已回答的唯一追问和当前手动映射建议。只有用户确认放弃或进程终止才清理；服务端失败不能清空客户端文本。

### AI-083：功能开关

服务端可以按地区、供应商、模型别名、契约版本和成本关闭智能能力。关闭结果必须快速返回受控状态；App 在全局加号仍显示五种手动入口，不反复重试造成成本或等待。

## 10. 供应商适配层

### AI-090：统一适配器职责

```text
ParseDraftRequest
→ ProviderRouter
→ ProviderAdapter
   ├── 构造供应商请求与结构化输出约束
   ├── 调用与超时
   ├── 解析供应商响应
   └── 转成 DraftEnvelope
→ Schema + 领域校验
→ 客户端
```

适配器不得包含记录保存逻辑，也不得向供应商开放工具调用、Web 搜索或数据库函数。

### AI-091：结构化输出

- 支持严格 JSON Schema 的供应商使用受支持的严格结构化输出；
- 只支持 JSON mode 的供应商仍必须在返回后执行完整 Schema 校验；
- JSON 有效不代表业务有效；日期、数量和跨字段仍由程序校验；
- 响应被截断、包含额外文本或未知字段按适配器策略修复一次或失败；
- 不把供应商原始字段结构暴露为产品契约。

### AI-092：模型配置

配置使用内部别名，例如 `draft-fast-primary`，映射到地区允许的具体供应商模型。每次配置记录：

- provider/model identifier；
- promptVersion、adapterVersion、contractVersion；
- temperature/随机性等受支持参数；
- 超时、最大输入/输出和成本上限；
- 地区、数据处理和健康状态；
- 评测 run ID 与通过时间。

更换具体模型不要求客户端发版，但必须先通过完整回归和灰度。

### AI-093：地区策略

- 中国大陆环境默认路由到合规可用的国内供应商；
- GPT 只在供应商支持且产品允许提供服务的地区启用；
- 适配器存在和测试通过不等于所有生产地区都开放；
- 发行地区未确认前保持配置能力，不在对外文案承诺某模型；
- 第三方服务清单按实际部署和地区生成。

## 11. 凭据、额度和防滥用

### AI-100：P0 产品凭据

- 产品供应商 API Key 只存服务端密钥管理系统；
- 不进入客户端代码、安装包、远程配置明文、日志或仓库；
- 客户端只持有短期匿名服务令牌，不具备直接调用产品供应商账号的权限；
- 密钥轮换不改变草稿契约。

### AI-101：匿名额度

P0 使用 Installation ID 派生的匿名服务注册与服务端签发令牌，结合 IP/令牌速率限制：

- 额度值服务端配置，不写死客户端；
- 客户端可查询粗粒度“可用/接近用完/已用完”，不需要精确到供应商 token；
- 卸载重装可能绕过安装额度是 P0 接受的有限风险；
- 异常滥用可按地区/版本关闭智能，不影响本地功能；
- 不能为防滥用偷偷生成持久设备指纹或读取联系人/广告 ID。

### AI-102：P1 自带 Key

- Key 保存在设备安全存储，不进入普通数据库、备份、同步、日志或遥测；
- 默认由客户端直接连接用户选择的供应商兼容接口，产品服务端不接触 Key；
- 如果某配置必须经平台代理，连接测试前明确说明 Key 和内容会经过生活有谱服务，并单独确认；
- 用户承担供应商费用和账户条款，界面显示最近非内容错误及删除 Key；
- 删除 Key 后清理会话和连接缓存，不删除已创建记录。

## 12. 数据处理与日志

### AI-110：数据流

P0 管理式智能创建的数据流：

```text
客户端当前会话原始输入
→ TLS
→ 生活有谱智能网关内存处理
→ 地区允许的供应商
→ 供应商响应
→ 网关 Schema/业务校验
→ 客户端确认页
→ 用户确认后本地领域数据库
```

网关不得把原始输入或完整响应写入业务数据库、普通日志、缓存队列、错误追踪或分析系统。

### AI-111：允许的运行元数据

可以记录：

- 随机请求 ID；
- 地区、模型别名和版本；
- 输入/输出长度分桶与 token 数；
- 延迟、供应商状态码映射、重试次数；
- 结果状态、记录类型、Schema/业务校验是否通过；
- 额度分桶和成本；
- 不含内容的 warning/error code。

不能记录用户输入哈希作为跨请求识别手段；短文本哈希也可能被字典反推。

### AI-112：供应商留存

- 上线前核验每个供应商的训练、滥用监控、默认留存、区域处理和删除控制；
- 优先选择不用于训练、最短可用留存和企业/零留存控制；
- 没有合同或配置证明时，隐私文案不得声称“供应商绝不保存”；
- 供应商条款变化触发安全和合规影响检查，必要时关闭路由并重新取得说明确认；
- 具体供应商和期限只在第三方服务清单维护，本文件不复制会变化的数值。

### AI-113：敏感内容

用户在智能输入中主动输入敏感内容时，首次说明已经告知本次文字会发送；产品不能在发送后假装从未处理。确认页可以建议将记录标敏感，但不得基于敏感推断记录诊断标签。已有 `aiAccess = denied` 的记录在 P1/P2 任何上下文选择中硬性排除。

## 13. 提示词安全与内容处理

### AI-120：用户文本永远是数据

- 用户输入中“忽略上面的规则”“调用接口”“删除记录”等文本只作为待整理内容；
- 供应商请求不提供工具、函数执行、浏览器、数据库或文件访问；
- 结构化输出只允许 Schema 字段，额外指令和 HTML 丢弃/转义；
- 生成文本在 UI 中按纯文本渲染，不执行 Markdown HTML、URL scheme 或脚本；
- 标题、标签和文件相关字符串进入领域层前按长度与路径安全规则校验。

### AI-121：内容拒绝与手动功能

智能服务可能因供应商策略拒绝内容，但生活有谱不应据此删除、举报或阻止用户在本地手动保存合法的私人记录。法律要求或明确恶意服务滥用另按安全规范处理；客户端只显示智能整理不可用和手动入口。

## 14. P1 多轮、多草稿与语音

### AI-130：多轮会话

- 会话历史由客户端保存受控结构，不上传无关对话；
- 每轮只发送原始输入、必要已确认字段、未解决问题和明确选择上下文；
- 服务器默认无状态或使用短期加密会话，最长 30 分钟无活动即失效；
- 用户能查看和结束当前智能会话；结束后清理历史；
- 多轮仍不能直接保存。

### AI-131：多草稿

- 一个输入最多生成 10 条草稿；
- 每条拥有临时 draftId、独立类型、来源、校验和取消状态；
- 跨草稿引用用临时 ID，全部确认事务可以映射正式 ID；
- 用户可以逐条确认，失败的一条不污染已明确确认的其他条；
- 涉及库存与清单联动时在保存前展示跨草稿总影响。

### AI-132：语音

- 麦克风只在用户主动开始录音时申请；
- 原始音频默认只用于转写，不进入长期备份或模型草稿日志；
- 转写文字先展示可编辑，再由用户提交智能创建；
- 语言、数字、日期和专有名词不确定时优先让用户修正文本；
- 转写供应商和音频留存单独披露。

### AI-133：已有记录上下文

用户通过本地搜索明确选择记录后：

- 默认只发送完成当前请求所需字段；
- 显示记录数量、类型和字段范围，不在确认文案展开敏感正文；
- `aiAccess = denied`、不可见空间或已删除记录不可选；
- 发送快照携带 revision，返回结果若记录已改变则重新确认；
- 模型仍没有数据库查询能力。

## 15. P2 查询、识别与修改建议

### AI-140：查询已有记录

- 应用先在有权限的数据中本地/服务端检索候选；
- 用户确认上下文后才把最小片段发送给模型；
- 回答必须引用本次上下文中的记录 ID/标题展示映射，不能杜撰数据库事实；
- 没有证据时明确“没有在所选记录中找到”；
- 查询本身不修改任何数据。

### AI-141：修改建议

模型只返回版本化 PatchDraft：目标 ID、baseRevision、字段旧值摘要、建议新值、来源和风险。客户端：

1. 重新读取目标和权限；
2. 对比 baseRevision；
3. 展示逐项差异；
4. 用户逐项确认；
5. 调用正常领域命令；
6. 对库存、删除、共享和批量操作使用加强确认。

模型不得返回可直接执行 SQL、文件路径或任意命令。

### AI-142：图片、小票和条形码

- 图像先在客户端预览和裁剪；发送范围及供应商单独说明；
- OCR/识别只产生草稿，数量、单位、日期、价格和物品逐字段来源标记；
- 一张小票的多个物品使用多草稿流程；
- 条形码外部商品库信息是第三方建议，不等于用户家中已有物品；
- 任何库存变化确认后由领域层创建不可变流水。

## 16. 版本与兼容

### AI-150：独立版本

| 版本 | 作用 |
| --- | --- |
| `contractVersion` | DraftEnvelope 和五种草稿机器结构。 |
| `promptVersion` | 系统指令、示例和输出指导。 |
| `adapterVersion` | 供应商请求/响应转换。 |
| `validationVersion` | 确定性校验规则组合。 |
| `capabilityProfileVersion` | 某客户端/阶段允许能力。 |

任一版本变化都能独立回滚。评测报告必须记录全部版本组合。

### AI-151：兼容规则

- 新增可选字段：旧客户端忽略但服务端不得要求；
- 新增必要字段或枚举：提高 contractVersion；
- 服务端至少支持当前公开版本和上一个兼容客户端版本；
- 客户端遇到未知必要版本不展示/保存草稿，转手动并提示升级；
- 已保存领域记录不依赖模型或草稿版本读取。
