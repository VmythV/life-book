## 1. 状态、范围与规范词

本文把 TD-006 的编码决定固化为 `scalarEncodingVersion = 1`。当前文件处于
`Draft + CANDIDATE`：实现者可以审阅并运行 oracle，但在 paired contract、oracle
自校验和 documentation registry 的 authority 激活提交完成前，生产持久化、备份、API
或原生桥不得依赖本文件。

本文覆盖 `EntityId`、`Instant`、`LocalDate`、`LocalTime`、`TimeZoneId`、
`ExactDecimal`、`SortKey`、`Revision`、`LongCounter` 及其通用 JSON 文本规则。
重复规则、tzdb 资产、SQLite DDL、备份容器和业务字段上限由各自合同拥有。

“必须”“不得”“应”“可以”分别对应 RFC 2119/8174 的 MUST、MUST NOT、SHOULD、
MAY。所有长度均为 ASCII code unit 数；parser 必须先做固定长度上限检查，再做单次线性
扫描或等价的有界处理。失败不回显完整非法输入。

## 2. 共同边界

| Rule ID    | 规则                                                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `SCL-0001` | 每个持久化或交换 schema 必须直接声明 `scalarEncodingVersion = 1`，或由其父容器版本唯一推导。                                           |
| `SCL-0002` | canonical parser 只接受本文列出的唯一编码；旧版导入、UI 编辑态或外部协议的宽松输入必须使用具名 normalizer，不能复用 canonical parser。 |
| `SCL-0003` | formatter 对一个领域值只能输出一种 canonical encoding，且 `parse(format(value))` 与 `format(parse(text))` 必须保持恒等。               |
| `SCL-0004` | TypeScript domain、SQLite row、JSON DTO、备份 DTO 和原生桥 DTO 是不同类型；转换只发生在受审 adapter 边界。                             |
| `SCL-0005` | parser 禁止借助 `Number(text)`、`parseFloat`、truthy/falsy、locale 日期解析或二进制浮点业务运算猜测输入。                              |
| `SCL-0006` | 超范围、未知、非 canonical 或无法安全表示的值必须使当前命令/导入 fail closed；不得截断、饱和、回绕或静默舍入。                         |

## 3. `EntityId`

### 3.1 领域与编码

| 层            | v1 表示                          |
| ------------- | -------------------------------- |
| Domain        | 不透明、带品牌的 UUIDv4 identity |
| SQLite        | `TEXT COLLATE BINARY`            |
| JSON / backup | canonical UUID 文本              |

`SCL-0101`：新 ID 必须由平台 CSPRNG 按 RFC 9562 UUID version 4 生成；不得使用
`Math.random`、时钟、设备 ID 或可预测 counter。

`SCL-0102`：canonical 文本恰好 36 个 ASCII 字符，匹配：

```text
^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
```

`SCL-0103`：nil UUID、uppercase、错误 version/variant、缺少连字符、额外空白和非
ASCII 字符均拒绝。普通 API、SQLite、备份和 canonical JSON 不执行 lowercase
normalization。受控旧版导入若要接受 uppercase，必须由独立 migration version 明示。

`SCL-0104`：ID 是不透明身份；创建后不改变、不回收，也不在不同品牌类型之间复用。
文本排序只能用作确定性 tie-break，不能推导创建时间或授权。

## 4. 时间标量

### 4.1 `Instant`

| 层                  | v1 表示                                       |
| ------------------- | --------------------------------------------- |
| Domain / TypeScript | UTC epoch milliseconds，safe integer `number` |
| SQLite              | `INTEGER` epoch milliseconds                  |
| JSON / backup       | `YYYY-MM-DDTHH:mm:ss.SSSZ`                    |

`SCL-0201`：支持范围为 proleptic Gregorian `0001-01-01T00:00:00.000Z` 至
`9999-12-31T23:59:59.999Z`，即 epoch milliseconds
`-62135596800000...253402300799999`。

`SCL-0202`：canonical 文本恰好 24 个 ASCII 字符，日期必须真实，小时
`00...23`，分钟/秒 `00...59`，毫秒恰好三位，大写 `T` 和 `Z`。闰秒 `:60`、
`+00:00`、省略/增加小数位、空白和自动日期溢出均拒绝。

`SCL-0203`：只有上层协议显式选择 offset normalizer 时，才可接受同样固定毫秒精度的
`YYYY-MM-DDTHH:mm:ss.SSS±HH:mm`。offset 小时为 `00...23`、分钟为
`00...59`；normalizer 立即换算为范围内的 epoch milliseconds，后续 formatter 只输出
UTC `Z` 形式。canonical parser 自身仍拒绝 offset。

`SCL-0204`：epoch 输入必须先验证 `Number.isSafeInteger` 和 `SCL-0201` 范围。业务
时刻不得替代单调计时，也不得决定跨设备冲突胜负。

### 4.2 `LocalDate`

`SCL-0211`：所有层使用恰好 10 个 ASCII 字符的 `YYYY-MM-DD`，年
`0001...9999`，月 `01...12`，日必须是 proleptic Gregorian 中该月的真实日期。

`SCL-0212`：闰年规则为“可被 4 整除，且不可被 100 整除，除非可被 400 整除”。
`0000`、非补零、斜线、datetime、offset、locale 文本及自动溢出均拒绝。

`SCL-0213`：`LocalDate` 不得经 UTC 午夜 `Instant` 代替。`TEXT COLLATE BINARY`
的 canonical 字典序与日期序一致。

### 4.3 `LocalTime`

| 层                  | v1 表示                              |
| ------------------- | ------------------------------------ |
| Domain / TypeScript | 自 `00:00:00` 起的整数秒 `0...86399` |
| SQLite              | `INTEGER`                            |
| JSON / backup       | `HH:mm:ss`                           |

`SCL-0221`：canonical 文本恰好 8 个 ASCII 字符；小时 `00...23`，分钟/秒
`00...59`。`24:00:00`、fraction、offset、日期、AM/PM 和非补零形式均拒绝。

`SCL-0222`：P0 UI 只创建秒为 `0` 的分钟值，这是 presentation 能力限制，不缩小
标量本身的 `0...86399` 值域。

### 4.4 `TimeZoneId`

`SCL-0231`：持久值是选定、随包 tzdb 引擎返回的 canonical IANA zone ID；`UTC` 是
允许的固定 canonical ID。纯 offset、`GMT+8`、缩写（如 `CST`）和未知 zone 拒绝。

`SCL-0232`：入口必须把值交给带明确 tzdb identity 的 resolver。resolver 返回
`canonical` 时保存原值；返回 `alias` 时保存其 canonical target；返回 `unknown` 时
拒绝。应用不得自行维护不带 tzdb 版本的全局 alias 表，也不得自行改写
`Etc/GMT±N` 符号。

`SCL-0233`：本 oracle 用注入的 resolver classification 验证上述 adapter 行为，不声明
完整 tzdb 数据集。canonical zone 清单、alias 映射、版本升级和 DST 行为由 IMP-123 的
time/tzdb 合同与 oracle 激活。

## 5. `ExactDecimal`

`ExactDecimal` 固定 scale 为 `3`：

```text
display value = scaled integer / 1000
```

`SCL-0301`：`scaled` 为 signed exact integer，范围
`-999999999999999999...999999999999999999`。对应 display 范围为
`-999999999999999.999...999999999999999.999`。

`SCL-0302`：JSON/API/backup canonical display text 的整数部分是 `0` 或不带前导零的
十进制正整数；可有 `-`；fraction 为 1～3 位且最后一位不得为 `0`。因此唯一零是
`0`，`1.0`、`1.230`、`-0`、`-0.000`、`+1`、指数、空白和分组符均不是 canonical。
canonical parser 最长接受 20 个 ASCII 字符，并在换算 scale 后执行 `SCL-0301` 范围
检查。

`SCL-0303`：formatter 从 scaled integer 生成 display text，补足三位计算后移除 fraction
尾零；scaled zero 永远输出 `0`。领域等值由 scaled integer 决定，所以非 canonical UI
输入 `1`、`1.0` 和 `1.000` 可由另一个具名编辑态 parser 表示同一值，但持久化前只能
输出 `1`。

`SCL-0304`：SQLite 保存 scaled integer 的 canonical signed decimal `TEXT`。唯一零为
`0`；负数以一个 `-` 开头；绝对值无前导零且最多 18 位。不得在 SQL 中转
`INTEGER/REAL`，也不得依赖十进制文本的字典序做数值比较。

`SCL-0305`：TypeScript/Hermes 的计算通过项目 `ExactInteger` 端口和固定
`jsbi@4.3.2` adapter 完成；只有 scalar 包可以 import JSBI。需要舍入的除法/比例不由本
合同默认处理，调用方必须选择经业务规则批准的具名模式。

## 6. `SortKey`

`SCL-0401`：逻辑值为 unsigned 128-bit `0...2^128-1`；所有持久化和交换层使用恰好
32 位 lowercase hex。SQLite 使用 `TEXT COLLATE BINARY`，其 canonical 字典序等于
数值序。uppercase、`0x`、短写、空白均拒绝。

`SCL-0402`：全零和全 `f` 是左右保留边界。parser 可以表示它们以执行算法，但普通项
assignment 必须拒绝这两个值。稳定列表序是 `(sortKey ASC, id ASC)`。

`SCL-0403`：相邻 `left < right` 且 `right - left > 1` 时，中点为：

```text
floor((left + right) / 2)
```

若无空位，返回 `sort_key_gap_exhausted`，不得使用浮点或返回任一边界。

`SCL-0404`：无空位时，在同一事务内先按当前 `(sortKey, id)` 稳定序排列 `n` 个既有项，
第 `i` 项（1-based）获得：

```text
floor(i * MAX / (n + 1)), MAX = 2^128 - 1
```

随后重新执行原插入。计算必须使用 exact integer；技术重排不改变业务 revision 或
`updatedAt`。

## 7. `Revision` 与 `LongCounter`

### 7.1 `Revision`

`SCL-0501`：所有层使用整数 number/`INTEGER`，范围 `1...4294967295`。创建值为 `1`。
输入必须是 safe integer，拒绝 string、零、负数、小数和范围外值。

`SCL-0502`：业务持久化改变执行 checked `+1`。最大值递增返回
`revision_exhausted`；不得归零、回绕或饱和。技术索引重建和 SortKey 重排不递增。

### 7.2 `LongCounter`

`SCL-0511`：逻辑范围为 non-negative signed 64-bit
`0...9223372036854775807`。TypeScript domain 使用 `ExactInteger`/不透明 value
object；SQLite、JSON、备份均使用 canonical decimal string；PostgreSQL 可用 `bigint`
但写出仍为 string。

`SCL-0512`：canonical text 最长 19 个 ASCII 字符；唯一零为 `0`，正数首位
`1...9`。负号、加号、前导零、小数、指数、空白、number JSON 值和最大值 + 1 均拒绝。

`SCL-0513`：比较和递增只能用 exact integer。最大值递增返回
`long_counter_exhausted`，所有普通写入、snapshot/control activation 和 notification
epoch 变更 fail closed。

## 8. JSON 与文本通则

| Rule ID    | 规则                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `SCL-0601` | Boolean 只接受 JSON `true`/`false`；string/number 不做 truthy/falsy 转换。SQLite 对应列只能是受 `CHECK` 约束的 `0/1 INTEGER`。      |
| `SCL-0602` | 协议 enum 是登记过的 lowercase `snake_case` ASCII token；显示文案、本地化文本和大小写变体不是协议值。                               |
| `SCL-0603` | “required + nullable” 必须显式出现为 `null`；只有被合同声明为 additive optional 的字段可 absent。`null`、absent、空串与零互不等价。 |
| `SCL-0604` | 文本以 UTF-8 原样往返；本层不得全局改变 normalization、大小写、空白或 emoji。                                                       |

## 9. 固定错误分类

Oracle 使用下列技术错误分类对齐跨实现拒绝结果；UI 可映射本地化文案，但不得借此改变
接受集合：

| Error code                                             | 含义                                                   |
| ------------------------------------------------------ | ------------------------------------------------------ |
| `invalid_entity_id`                                    | EntityId 长度、语法、version、variant 或 nil 非法。    |
| `invalid_instant` / `instant_out_of_range`             | Instant 语法/日期非法，或换算后超范围。                |
| `invalid_local_date` / `invalid_local_time`            | 本地日期/时间非 canonical 或不真实。                   |
| `invalid_time_zone_id` / `unknown_time_zone`           | zone 词法不允许，或 resolver 不认识。                  |
| `invalid_exact_decimal` / `exact_decimal_out_of_range` | decimal 非 canonical，或 scaled 超范围。               |
| `invalid_scaled_integer`                               | SQLite scaled integer text 非 canonical 或超范围。     |
| `invalid_sort_key` / `reserved_sort_key`               | key 编码非法，或试图分配保留边界。                     |
| `sort_key_gap_exhausted`                               | 两个有序 key 之间没有整数空位。                        |
| `invalid_revision` / `revision_exhausted`              | revision 非法，或最大值递增。                          |
| `invalid_long_counter` / `long_counter_exhausted`      | long 非 canonical/超范围，或最大值递增。               |
| `invalid_json_scalar`                                  | boolean、enum、presence/null 或 UTF-8 边界违反本合同。 |

## 10. Oracle 与激活门

`SCL-0701`：v1 oracle manifest 必须符合
[oracle-manifest-v1.schema.json](../testing/oracle-manifest-v1.schema.json)，列出完整
`contracts[]` 集合和每个 fixture 的 SHA-256；manifest 不列自身 checksum。

`SCL-0702`：oracle checker 不得 import 产品 scalar 实现。当前 Node checker 使用原生
exact integer 与独立 proleptic Gregorian 算法重算 expected；这只证明固定预期可执行，
不等于 TypeScript/Hermes、Android、SQLite、备份或服务端实现 conformance。

`SCL-0703`：转为 `Normative + CANDIDATE` 需要 manifest schema 自检与本 oracle 全部
通过；转为 `ACTIVE` 还需要 documentation registry 的单独审计提交。M2 首条真实数据前，
所有实际 consumer 的 conformance evidence 仍必须绑定当前 Git、contract digest、oracle
digest、实现版本和平台。
