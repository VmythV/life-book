# 生活有谱产品路线图

> 项目代号：`life-book` · 版本：v0.1 · 日期：2026-07-21 · 状态：已确认的优先级基线

本文把已经讨论确认的能力分为 P0、P1 和 P2。优先级表示交付顺序，不代表功能的重要性。产品决策的背景和约束见[产品决策记录](product-decisions.md)，详细行为见[产品功能说明](product-features.md)。

## 1. 优先级定义

| 优先级 | 含义 | 判断标准 |
| --- | --- | --- |
| P0 | 首个可用版本 | 缺少该能力会破坏“记录、提醒、查找、备份与恢复”的核心闭环。 |
| P1 | 首发后的增强版本 | 核心闭环已经成立，用于改善同步、输入效率和记录深度。 |
| P2 | 扩展版本 | 建立在账号、同步或成熟数据基础上的家庭协作和智能能力。 |
| 待讨论 | 尚未排期 | 产品方向或技术方案尚未形成结论，不能默认进入开发。 |

## 2. P0：首个可用版本

P0 的目标是让一个用户无需注册，在手机上完整完成以下过程：

> 能记录 → 能提醒 → 能找到 → 能备份 → 能恢复

### 2.1 平台与使用方式

- 同时提供 iOS 和 Android 手机 App。
- 手机尺寸和触摸操作优先。
- 免登录即可使用完整手动功能。
- 核心数据保存在本机。
- 创建、修改、搜索和处理记录支持离线使用。
- Web 端不进入 P0。

### 2.2 主导航

- **今天**：聚合逾期、今天、即将发生和低库存内容。
- **生活簿**：浏览、搜索和整理全部记录。
- **家中**：管理家庭物品、库存流水和补货需求。
- **我的**：管理通知、分类、标签、备份、隐私和智能服务。
- **全局加号**：默认打开一句话创建，同时保留五种手动入口。

### 2.3 五种记录

#### 重复事项

- 每天、每周、每月和每年重复。
- 每隔 N 天、周或月重复。
- 指定每周星期几或每月日期。
- 开始日期、可选结束日期和提醒时间。
- 本次完成、跳过、逾期和稍后提醒。
- 本次状态不影响后续周期生成。
- 已经发生的历史记录不被规则修改破坏。

#### 清单

- 空白清单、分组和清单项目。
- 项目排序、数量、说明和完成状态。
- 截止时间与提醒。
- 清单模板与使用实例分离。
- 从模板创建实例不会修改原模板。
- 实际清单可以另存为模板。

#### 备忘

- 标题、正文、分类和标签。
- 图片或附件的基础支持。
- 置顶、搜索和归档。
- 可选的一次或多次提醒。
- 提醒结束后继续保留备忘内容。

#### 重要日期

- 一次性日期和每年重复日期。
- 公历日期。
- 可选起始年份。
- 提前多天和当天的多次提醒。
- 生日、纪念日与到期日使用不同展示文案。

#### 家庭物品

- 名称、图片、数量、单位、位置和最低库存。
- 买入、使用、调整、报废或丢失。
- 每次变化形成库存流水。
- 低库存提醒。
- 一键加入采购清单。

### 2.4 今天与提醒

- 到达用户设定时间时默认发送一次系统通知。
- 未处理内容在“今天”持续显示为逾期。
- 默认不连续催促，用户可以主动开启并设置间隔。
- 通知提供完成、跳过和稍后提醒快捷操作。
- 重要日期支持多次提前提醒。
- 低库存只在首次进入不足状态时提醒。
- 没有通知权限时仍显示应用内提醒和权限说明。
- 离线可完成的提醒不依赖实时联网。
- 用户明确设定的准确时间不被应用勿扰规则擅自调整。

### 2.5 搜索与整理

- 搜索标题、正文、清单项目、物品名称和存放位置。
- 按类型、分类、标签、状态和日期筛选。
- 用户自定义分类和标签。
- 置顶或收藏常用记录。
- 归档并保留搜索能力。
- 删除内容进入回收站并默认保留 30 天。

### 2.6 智能创建

- 在全局加号中使用文字进行一句话创建。
- 自动判断五种记录类型。
- 一次输入默认生成一条结构化草稿。
- 对关键歧义进行一次简短追问。
- 模型推断的字段在确认单中标记为系统建议。
- 程序校验日期、重复规则、数量和提醒字段。
- 用户修改或确认后才写入数据库。
- 取消或模型失败时不写入任何记录。
- 模型失败时保留原始输入并转入手动表单。
- 建立统一模型供应商适配层。
- GPT 与千问至少各提供一种可用适配配置。
- 普通用户使用内置智能服务，不需要配置 API Key。
- 内置服务可设置免费额度，但手动能力永久免费可用。
- P0 模型上下文只包含本次输入、日期、时区和必要字段定义。

### 2.7 隐私、备份与恢复

- 数据保存在应用私有目录。
- 支持 Face ID、指纹或设备密码应用锁。
- 单条记录可以标记为敏感内容。
- 敏感记录可以禁止用于智能功能。
- 通知可以显示完整内容、只显示标题或完全隐藏。
- 敏感记录的通知默认不展示标题和正文。
- API Key 使用安全存储，不进入日志、普通数据库或代码仓库。
- 创建加密备份文件。
- 从加密备份恢复全部数据。
- 导出结构化或可阅读数据。
- 未加密导出前必须明确提示风险。
- 永久删除、清空回收站和删除空间需要二次确认。

### 2.8 数据结构预留

P0 不提供家庭共享，但记录结构需要预留：

- 个人空间
- 家庭空间
- 记录所属空间
- 记录创建人
- 记录最后修改人
- 重要操作记录

这些字段用于避免后续增加账号、同步和家庭协作时推翻本地数据结构。

## 3. P1：增强版本

P1 的目标是让数据跨设备可靠流动，并减少复杂内容的录入成本。

### 3.1 账号与同步

- 可选账号注册与登录。
- 加密云备份。
- iOS 与 Android 跨设备同步。
- 同步冲突检测和可理解的处理方式。
- 本地数据迁移到账号空间。
- 退出登录后保留或清除本地数据的明确选择。

### 3.2 智能创建增强

- 对话式补充缺失信息。
- 一次输入生成多条草稿。
- 逐条修改、取消或全部确认。
- 语音输入。
- 用户主动选择一条已有记录作为上下文。
- 高级用户配置自己的 GPT、千问或兼容接口 API Key。
- 供应商状态、失败原因和额度状态可见。

### 3.3 日期与物品增强

- 农历重要日期。
- 物品保质期。
- 同一物品的多个批次。
- 购买日期、价格和来源。
- 保修期限与到期提醒。
- 同一物品的多个存放位置。

### 3.4 分享与整理增强

- 将清单导出或分享给他人。
- 更完整的附件支持。
- 跨设备备份管理。
- 数据导入预览和冲突提示。

## 4. P2：扩展版本

P2 的目标是让生活有谱从个人工具扩展为家庭共同维护的生活空间。

### 4.1 家庭空间与成员协作

- 创建或加入家庭空间。
- 个人空间默认私密。
- 只有主动放入家庭空间的记录才共享。
- 家庭创建者邀请和移除成员。
- 普通成员查看、新建和编辑共享记录。
- 共同勾选清单、完成事项和维护库存。
- 展示谁在什么时间做了什么修改。
- 高风险操作只允许家庭创建者执行。
- 后续根据真实需求增加更细权限。

### 4.2 智能能力扩展

- 条形码扫描。
- 购物小票识别。
- 物品图片识别。
- 根据库存生成采购建议。
- 查询已有记录。
- 基于已有记录生成新草稿。
- 提出修改已有记录的草稿，经用户逐项确认后执行。
- 敏感记录始终遵守禁止用于智能功能的设置。

### 4.3 Web 与生态

- Web 端查看和批量整理。
- 多语言。
- 模板分享。
- 公共模板市场。
- 生活数据趋势与回顾。
- 家庭成员更细粒度权限。

## 5. P0 明确排除项

下列能力不应以“顺手一起做”为理由进入 P0：

- 强制注册和登录
- 云同步
- 家庭成员共享
- Web 端
- 农历日期
- 语音输入
- 一次生成多条记录
- 图片、小票和条形码识别
- AI 查询或修改已有记录
- 复杂统计和习惯分析
- 公共模板市场
- 正式会员和计费系统
- 多语言

如果某项排除能力成为发布前置条件，需要重新讨论并同步调整范围、工期和验收标准。

## 6. P0 发布门槛

P0 发布前必须通过以下端到端验证：

1. 用户安装后无需注册即可使用。
2. 用户可以手动创建五种记录。
3. 用户可以用一句话生成并确认一条记录草稿。
4. 创建成功后，记录出现在正确列表和“今天”页面。
5. 用户在正确时间收到一次不重复的提醒。
6. 完成、跳过或稍后提醒后，状态计算正确。
7. 重复事项的本次状态不破坏后续周期。
8. 清单实例的修改不影响模板。
9. 物品数量与库存流水计算一致。
10. 用户可以搜索并找到过去的记录。
11. 没有网络时，除智能创建外的核心功能仍然可用。
12. 模型失败时，用户输入不会丢失。
13. 应用锁和敏感通知按设置生效。
14. 用户能够创建备份、删除本地数据并成功恢复。
15. 工作区中不包含 API Key 或其他生产密钥。

## 7. 尚未确定的事项

以下事项尚未形成产品决策，不属于本路线图的既定结论：

- 客户端、服务端、数据库和部署技术方案
- 正式商业模式与具体价格
- 内置智能服务的免费额度数值
- 端到端加密的覆盖范围
- P0 的具体发布日期
