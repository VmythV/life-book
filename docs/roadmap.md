本文只分配交付阶段。需求含义以 `PR-*` 所在产品需求基线为准，质量目标以 `QR-*` 所在质量属性基线为准，验收步骤由验收规范负责。

## 1. 阶段定义

| 阶段 | 目标 | 完成结果 |
| --- | --- | --- |
| P0 | 首个可用版本 | 一个用户无需注册，在手机上完成“能记录 → 能提醒 → 能找到 → 能备份 → 能恢复”。 |
| P1 | 增强版本 | 数据可以跨设备可靠流动，复杂输入更省力，记录信息更完整。 |
| P2 | 扩展版本 | 个人工具扩展为家庭共同维护的生活空间，并增加成熟数据上的智能与生态能力。 |
| 待讨论 | 尚无交付承诺 | 需求存在，但进入阶段前还需要研究、商业、法律或技术决策。 |

优先级表示交付顺序，不表示某项长期价值较低。没有在本路线图中分配到某阶段的用户可见能力不得被默认实现。

## 4. P0 发布门槛

P0 必须同时满足以下结果门槛；具体 Given/When/Then 场景由验收规范唯一维护。

### 4.1 核心闭环

1. 无需注册或教程即可创建第一条真实记录。
2. 五种记录均能完成手动创建、查看、编辑、整理、归档、删除和恢复的适用流程。
3. 一句话输入可以产生并确认一条合法草稿；失败时输入保留并可转手动。
4. 创建后记录出现在正确列表和适用的“今天”区域。
5. 搜索能在离线状态找到历史记录。
6. 用户能创建加密备份、清除测试数据并完整恢复。

### 4.2 业务正确性

1. 重复实例互相独立，规则修改不破坏历史。
2. 清单实例不修改模板，进度和重新打开规则正确。
3. 重要日期的事件种类、历法、重复方式和起始年份互不混淆。
4. 当前库存等于有效流水结果，低库存使用 `<=`，同一低库存周期不重复通知。
5. 不适用的记录类型不出现完成或跳过动作。
6. 归档、删除和永久删除正确取消未来提醒并保留规定历史。

### 4.3 提醒与平台

1. 时间、重复和提醒测试向量全部通过。
2. 创建、编辑、完成、跳过、归档、删除、恢复、时区变化和升级后调度对账正确。
3. 系统通知动作幂等且不会产生重复状态或库存流水。
4. 权限拒绝时记录仍可保存，应用内状态可见，降级说明准确。
5. 至少完成一次覆盖 iOS 和主要 Android 厂商行为的连续 14 天真机测试。

### 4.4 数据与安全

1. 数据库、附件、设备密钥和服务端密钥符合安全规范。
2. 敏感内容在通知、预览、后台快照、导出和日志中按设置保护。
3. 错误口令、损坏备份、存储不足和旧格式恢复均不改变原数据。
4. 工作区、构建产物和日志中不存在生产密钥或真实生活内容。
5. P0 所有数据库迁移和支持备份版本完成往返验证。

### 4.5 质量与发布准备

1. 所有 P0 `PR-*` 至少映射一个验收场景并通过。
2. P0 `QR-*` 达到本文件和质量基线中的门槛。
3. 没有发布阻断或高严重度未解决缺陷。
4. 隐私说明、权限用途、第三方服务、支持和商店披露与实际构建一致。
5. 监控、智能服务关闭开关、发布回滚和用户支持路径已演练。

6. 智能查询只使用用户本次授权和过滤后的上下文，敏感禁用标记始终优先。
