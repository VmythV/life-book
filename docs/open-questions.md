# 生活有谱未决事项登记表

> 项目代号：`life-book` · 版本：v1.0 · 更新日期：2026-07-26 · 状态：持续维护  
> 权威范围：尚未确定事项、临时默认值、阻塞阶段与关闭证据  
> 依赖文档：[文档治理规范](documentation-governance.md)、[产品决策记录](product-decisions.md)、[产品路线图](roadmap.md)

本文集中管理无法仅凭现有产品原则确定的事项。其他规范不得散落 `TODO`、`TBD` 或含糊的“后续再说”；未决内容必须登记在这里，并给出在决定形成前可以安全采用的默认处理。

## 1. 使用规则

### 1.1 状态

| 状态 | 含义 |
| --- | --- |
| 开放 | 需要产品负责人、外部主体或真实研究结果作出选择。 |
| 采用默认值 | 当前阶段按明确默认值实施；到达指定决策门前可以调整。 |
| 等待外部核验 | 依赖商标、商店、法律、供应商或平台审核结果。 |
| 已关闭 | 已形成产品决策、技术决策或正式规范，并链接关闭证据。 |

### 1.2 阻塞原则

- “阻塞 P0 开发”表示相关纵向切片不得开始编码。
- “阻塞 P0 公开测试”表示可以开发和内部测试，但不能向真实用户公开提供。
- 只阻塞 P1/P2 的事项不得拖延 P0，P0 数据结构应保留明确扩展点。
- 采用默认值的事项不阻塞当前阶段；改变默认值时必须执行文档和实现影响检查。

## 2. 当前开放事项

### OQ-001：首发地区与分发渠道

| 属性 | 内容 |
| --- | --- |
| 状态 | 开放 |
| 需要决定 | 仅中国大陆、仅海外，或大陆与海外同时首发；包括 iOS App Store、Google Play 和国内 Android 商店范围。 |
| 为什么不能代替决定 | 它影响模型供应商、服务部署区域、备案、隐私文本、推送通道、支付和商店审核。 |

| 阻塞阶段 | P0 公开测试，不阻塞本地功能和多供应商适配开发。 |
| 最晚决定 | 创建生产环境、申请应用标识和提交商店材料之前。 |
| 关闭证据 | 在产品决策记录新增发行地区决定，并更新技术架构、第三方服务和商店披露。 |

### OQ-003：开发团队技术偏好

| 属性 | 内容 |
| --- | --- |
| 状态 | 采用默认值 |
| 需要决定 | 团队是否有明显的 React/TypeScript、Dart/Flutter 或原生开发经验优势。 |
| 当前默认 | 无已知偏好时使用 React Native、Expo Development Build/CNG 和 TypeScript；选择依据记录在技术 ADR。 |

| 关闭证据 | 客户端栈 ADR 被接受且工程骨架完成。 |

### OQ-004：提醒可靠性的产品承诺

| 属性 | 内容 |
| --- | --- |
| 状态 | 采用默认值 |
| 需要决定 | 是否接受移动操作系统约束下的“已调度提醒尽力准时”，还是要求用户长期不打开 App 时任意复杂规则仍无限期准点。 |
| 当前默认 | 接受平台边界：已经成功交给系统的提醒可离线工作；App 每次获得运行机会时补齐滚动窗口。系统勿扰、通知摘要、权限、设备关机、厂商省电和滚动窗口之外的复杂提醒不作绝对送达承诺。 |
| 阻塞阶段 | 不阻塞 P0；若要求绝对承诺，则阻塞提醒实现并需要重新评估远程推送和 P0 范围。 |
| 关闭证据 | 产品决策、提醒规范、内容设计和验收规范使用同一承诺。 |

### OQ-005：加密备份口令的恢复能力

| 属性 | 内容 |
| --- | --- |
| 状态 | 采用默认值 |
| 需要决定 | 用户忘记独立备份口令后，是否需要由产品方找回。 |
| 当前默认 | P0 不托管备份密钥，忘记口令后无法恢复；创建备份和恢复时必须明确说明。 |
| 原因 | P0 无账号、数据本地优先；官方找回需要账号、密钥托管和新的信任边界。 |
| 阻塞阶段 | 不阻塞 P0；要求找回能力时至少进入 P1 并新增安全决策。 |
| 关闭证据 | 数据生命周期、安全规范和用户文案采用同一规则。 |

### OQ-007：商业模式与智能额度

| 属性 | 内容 |
| --- | --- |

### OQ-010：内置智能服务的匿名防滥用强度

| 属性 | 内容 |
| --- | --- |
| 状态 | 采用默认值 |
| 需要决定 | 无账号 P0 是否需要强设备证明、手机号或其他高摩擦验证。 |
| 当前默认 | 使用随机安装标识、服务端签发的匿名令牌、IP 与令牌组合限流、区域和供应商配额；接受卸载重装可能绕过设备额度的有限风险。异常流量可以整体关闭智能服务，手动功能继续可用。 |
| 阻塞阶段 | 不阻塞 P0；真实滥用超过成本护栏时重新决策。 |

## 3. 已在本轮规范中收敛的事项

以下项目源于旧文档歧义，不再要求产品负责人额外选择；对应专项规范必须给出唯一规则，完成后在本表补充关闭链接。

| 编号 | 原歧义 | 统一方向 | 计划关闭文档 |
| --- | --- | --- | --- |
| OQ-101 | 所有提醒是否都能“完成/跳过” | 动作由来源类型决定；只有重复事项实例有完成/跳过，其他类型使用查看、知道了、稍后等适用动作。 | `business-rules.md`、`reminders-and-notifications.md` |
| OQ-102 | 低库存使用 `<` 还是 `<=` | 统一为当前数量小于或等于最低库存阈值。 | `business-rules.md` |
| OQ-103 | P0 与 P1 智能追问边界 | P0 最多一轮、一个关键问题；仍歧义则转手动。P1 才支持保留上下文的多轮补充。 | `intelligence-spec.md` |
| OQ-104 | P0 是否支持通用导入 | P0 只支持本产品加密备份的整体恢复；通用结构化数据导入及合并预览属于 P1。 | `data-lifecycle.md` |
| OQ-105 | 默认个人空间能否删除 | 默认个人空间实体始终存在；P0 只能清除本机数据。删除家庭空间属于 P2 高风险操作。 | `business-rules.md`、`family-sharing.md` |
| OQ-106 | “置顶”和“收藏”是否不同 | 统一使用“置顶”；不再另设收藏状态，未来需要时通过新决策增加。 | `glossary.md`、`business-rules.md` |
| OQ-107 | 重要日期的“日期类型” | 拆为事件种类、历法、重复方式、日期值和可选起始年份。 | `domain-model.md` |
| OQ-108 | P0 API Key 保存位置 | 产品内置供应商密钥仅在服务端；P1 用户自带 Key 才保存在设备安全存储。 | `security-and-privacy.md`、`intelligence-spec.md` |
| OQ-109 | “不会保存智能输入”的范围 | 明确区分在途处理、供应商处理、临时内存、业务数据库、日志和遥测；确认前不写入生活记录数据库。 | `intelligence-spec.md`、`security-and-privacy.md` |
| OQ-110 | P2 基础权限与细粒度权限同阶段冲突 | P2 首期只交付空间级角色权限；逐记录授权作为后续扩展，不纳入 P2 首期门槛。 | `family-sharing.md`、`roadmap.md` |

```markdown
| 属性 | 内容 |
| --- | --- |
| 状态 | 开放 / 采用默认值 / 等待外部核验 / 已关闭 |
| 需要决定 | 一个可回答的问题 |
| 当前默认 | 决定形成前唯一允许的实现方式 |
| 阻塞阶段 | P0 开发 / P0 公开测试 / P1 / P2 / 不阻塞 |
| 最晚决定 | 明确的交付门或触发条件 |
| 关闭证据 | PD、ADR 或专项规范链接 |
```
