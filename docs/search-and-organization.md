# 生活有谱搜索与整理规范

> 项目代号：`life-book` · 版本：v1.0 · 更新日期：2026-07-26 · 状态：搜索基线
>
> 权威范围：搜索语义、索引范围、规范化、排序、筛选、分类标签和敏感结果保护
>
> 不负责：数据库 FTS 实现、页面视觉、通用字段定义和分类标签生命周期事务
>
> 依赖文档：[产品需求基线](product-features.md)、[业务规则](business-rules.md)、[领域模型](domain-model.md)、[信息架构](information-architecture.md)

搜索的目标是“记得大概也能找到”，同时保持离线、私密和可解释。索引是可重建缓存，记录、清单项目和库存流水等领域数据才是权威来源。

## 1. 范围与入口

### SRCH-001：P0 搜索上下文

- SCR-021 在当前默认个人空间搜索生活记录。
- 默认排除归档和回收站；用户可以显式包含归档。
- 回收站只在 SCR-434 内单独搜索，不与正常结果混合。
- 清单模板在模板库内搜索，不作为生活记录结果混入 SCR-021。
- “家中”物品列表可以使用同一搜索内核并预设 `recordType = household_item`。
- P0 没有跨空间和云端搜索。

### SRCH-002：P1/P2 上下文

- 默认只搜索当前空间；切换到“所有可见空间”必须是用户明确操作，并在每个结果标明空间。
- 服务端搜索必须重复执行权限过滤，不能依赖客户端先筛掉不可见对象。
- 敏感和禁止用于智能功能影响模型上下文，不影响用户本人有权限的本地搜索。
- Web 与移动端使用相同筛选语义，排名可以因呈现空间不同调整，但不能遗漏完全匹配。

## 2. 索引范围

### SRCH-010：字段和权重

| 内容 | P0 是否索引 | 基础权重 | 说明 |
| --- | :---: | ---: | --- |
| 记录标题/物品名称 | 是 | 100 | 最重要；完全匹配和前缀额外加权。 |
| 分类名称 | 是 | 60 | 分类重命名后重建关联文档。 |
| 标签名称 | 是 | 60 | 多标签去重。 |
| 家庭物品存放位置 | 是 | 55 | 支持“储物间”等查找。 |
| 清单项目标题 | 是 | 50 | 命中时显示所属清单和匹配项目摘要。 |
| 备忘正文 | 是 | 40 | 敏感结果不展示正文片段。 |
| 记录通用说明 | 是 | 35 | 五种类型适用。 |
| 清单项目说明 | 是 | 25 | 权重低于项目标题。 |
| 附件显示文件名 | 是 | 20 | 只索引文件名，不索引私有路径。 |
| 库存流水备注 | 否 | — | P0 只在物品详情内筛选，避免全局噪声。 |
| 附件二进制/OCR 文本 | 否 | — | 图片和文件内容搜索属于后续能力。 |
| 提醒/通知诊断 | 否 | — | 不是生活内容。 |
| 操作记录 | 否 | — | 家庭审计有独立筛选。 |

基础权重是逻辑相对值，物理引擎可以等比例转换。新增索引字段必须评估隐私、容量、迁移和排名回归。

### SRCH-011：索引文档边界

一个根记录对应一份逻辑搜索文档，清单项目作为嵌套可命中内容，不在全局结果中产生脱离清单的独立记录卡。家庭物品库存流水不生成独立全局搜索结果。

### SRCH-012：生命周期过滤

- active：默认可搜索；
- archived：只有“包含归档”开启时可搜索；
- trashed：只在回收站索引域可搜索；
- purged：立即从全部索引移除；
- 子对象跟随根记录域，不因自身软删除留在命中片段。

索引域之间不能通过仅 UI 隐藏实现；查询本身必须带生命周期条件。

## 3. 文本规范化

### SRCH-020：统一规范化管线

索引和查询必须使用同一版本化管线：

1. Unicode NFKC 规范化；
2. 与地区无关的 Unicode 大小写折叠；
3. 全角/半角兼容折叠；
4. 连续空白归一为单一分隔；
5. 常用标点作为边界，但保留原文用于展示；
6. 为拉丁字母生成词、前缀和可配置重音折叠形式；
7. 为汉字连续文本生成能够支持 1–3 字部分匹配的索引单元；
8. 为数字、日期片段、型号中的字母数字组合保留连续 token。

规范化结果只用于索引和唯一性比较，不改写用户显示内容。

### SRCH-021：中文与短词

- 单个汉字查询必须可匹配标题、标签和物品位置，不能因分词器把整句视为一个词而失效。
- 两到三个汉字应支持连续子串匹配，例如“滤芯”命中“空调滤芯型号”。
- P0 不要求拼音、首字母或繁简自动转换；输入“lvxin”不保证命中“滤芯”。
- 不维护可能误删生活词语的中文停用词表。
- 高开销的任意模糊编辑距离不进入 P0；拼写建议属于后续增强。

### SRCH-022：型号、数字和单位

- `ABC-123`、`abc123` 和 `ＡＢＣ－１２３` 应能通过规范化匹配同一型号，同时完全格式匹配排名最高。
- 数字和单位可以分开匹配，但搜索结果不得用单位换算改变原内容。
- 精确日期值默认不加入遥测；本地搜索可以匹配用户明确输入的显示年月日文本。

### SRCH-023：查询限制

- 去除首尾空白后空查询不执行全文搜索。
- 单次查询最长 200 个码点；超出时保留输入并提示缩短，不静默截断。
- 最多解析 20 个有效 token，超出时提示缩小范围。
- 特殊字符不能被直接拼接进数据库查询语句；所有查询参数化或通过安全查询 AST。

## 4. 查询语义

### SRCH-030：默认 AND 语义

多个查询 token 默认都必须在同一根记录的任意索引字段中出现，字段可以不同。例如“旅行 证件”可以分别命中清单标题和清单项目。

P0 不提供用户可见布尔语法。引号、减号、冒号等按普通内容或边界处理，避免用户误触隐藏规则。

### SRCH-031：匹配等级

从高到低：

1. 完整标题规范化相等；
2. 标题从查询开始的前缀匹配；
3. 标题连续子串匹配；
4. 分类、标签或位置完全匹配；
5. 清单项目标题匹配；
6. 备忘正文或通用说明匹配；
7. 附件文件名匹配。

满足多个等级时累加但设上限，避免超长备忘因重复出现同一词压过标题完全匹配。

### SRCH-032：稳定排名

最终排名综合：

```text
文本匹配等级
+ 字段权重
+ 同一字段中查询 token 的接近程度
+ 适度的最近修改衰减
```

不使用置顶改变全文相关性；完全标题匹配永远高于仅正文匹配。分数相同按 `updatedAt DESC, id ASC` 稳定排序，刷新不得随机跳动。

### SRCH-033：命中摘要

- 优先显示权重最高的匹配字段和有限上下文。
- 一个结果最多展示 2 个匹配片段，每段最多约 120 个显示字符。
- 清单项目命中显示项目标题与所属分组；点击进入清单并定位项目。
- 敏感记录只显示通用占位或用户允许的标题，不显示正文、项目、位置或附件名片段。
- 规范化匹配的高亮映射回原文字符范围，不能展示规范化缓存文本。

## 5. 搜索页面状态

### SRCH-040：空查询

空查询页面显示：

- 支持搜索的内容说明；
- 常用类型筛选快捷入口；
- 可选最近修改记录，但遵循敏感预览；
- 当前会话内的查询可以保留在内存以便返回。

P0 不持久化原始搜索词历史，也不把搜索词上传。未来增加最近搜索前必须提供本地清除入口和敏感保护。

### SRCH-041：无结果

无结果时：

- 显示当前查询和已应用筛选；
- 提供清除部分筛选、包含归档或检查类型的动作；
- 不建议把查询内容直接发送给模型；
- 不创建虚假匹配或自动修改用户文本。

### SRCH-042：索引处理中

新建/编辑提交后，目标记录必须立即能从详情和所属列表打开。搜索索引若尚未完成：

- 当前会话对刚保存记录使用小范围权威数据补偿，避免“刚保存却搜不到”；
- 设置或诊断显示索引正在整理；
- 达到 QR-011 时间后仍未完成记为索引故障并重试；
- 不阻塞其他记录读写。

## 6. 筛选语义

### SRCH-050：通用筛选

| 筛选 | 语义 |
| --- | --- |
| 类型 | 选择五种根记录类型之一或多选。 |
| 分类 | 一条记录属于所选任一分类；“未分类”是显式选项。 |
| 标签 | 默认 AND：记录必须具有全部所选标签；UI 可以切换 OR 作为后续增强。 |
| 生命周期 | active / archived；trashed 只在回收站。 |
| 敏感 | 全部 / 仅普通 / 仅敏感；不作为默认暴露入口。 |
| 日期范围 | 按用户选择的业务日期类型过滤，不含糊使用 updatedAt。 |
| 需要关注 | 当前能产生今天关注项的记录。 |

### SRCH-051：状态筛选按类型

| 类型 | 可用业务状态 |
| --- | --- |
| 重复事项 | 有待完成、存在逾期、已结束；完成/跳过属于实例，筛选结果仍返回根记录。 |
| 清单 | open、completed、overdue。 |
| 备忘 | 有待查看提醒、无提醒；没有 completed/overdue。 |
| 重要日期 | 今天、即将到来、历史；没有 completed/overdue。 |
| 家庭物品 | 正常库存、低库存、无阈值；没有 completed。 |

混合类型时只展示对当前类型集合有意义的状态，不能把不适用状态默认为 false 后误导用户。

### SRCH-052：日期范围字段

用户选择日期范围时必须选择或由单一类型确定含义：

- 创建时间；
- 最近修改时间；
- 重复事项下一发生日；
- 清单截止日；
- 备忘下一提醒；
- 重要日期下一发生日；
- 家庭物品最近流水时间。

混合类型默认使用创建/修改时间；不得把不同业务日期塞入同一“日期”字段而不说明。

## 7. 列表排序

### SRCH-060：生活簿

P0 提供：

- 最近修改（默认）：`updatedAt DESC`；
- 最近创建：`createdAt DESC`；
- 标题：按当前语言的稳定本地排序规则；
- 业务日期：只在单一适用类型筛选下开放。

置顶记录先形成置顶分区，分区内继续使用当前排序。搜索结果不用置顶分区，按 SRCH-032 相关性。

### SRCH-061：家中

家庭物品列表提供：

- 需要补货优先（默认）：低库存在前，再按标题；
- 最近变化：最后库存流水时间；
- 名称；
- 存放位置。

置顶在非低库存分区内优先；低库存业务状态始终高于置顶。

### SRCH-062：清单和项目

- 清单项目默认按 `sortKey`；完成项目可以由用户设置留在原位或折叠到底部，P0 默认留在原位。
- 分组顺序和组内项目顺序分别稳定。
- 全文搜索定位项目不永久改变用户排序。

## 8. 分类与标签管理

### SRCH-070：唯一性反馈

分类/标签名称按 BR-020、BR-021 规范化比较。用户输入与现有名称冲突时，选择现有对象并提供重命名/合并入口，不能创建仅大小写或全半角不同的重复项。

### SRCH-071：删除影响预览

删除前显示：

- 使用该分类或标签的记录数量，不显示敏感标题；
- 删除只移除归类、不删除记录；
- 同步/家庭阶段显示影响空间和待同步状态。

分类删除后记录变为未分类；标签删除后关系移除。搜索索引在同一提交批次标记重建。

### SRCH-072：合并

- 选择同空间目标对象；
- 预览源和目标使用量；
- 一次事务迁移记录关系、去重并删除源对象；
- 目标名称、颜色和排序保持不变，用户可以随后编辑；
- 操作可在短暂撤销窗口内通过保存的变更批次恢复，P1/P2 同步后按审计规则处理。

## 9. 索引一致性与重建

### SRCH-080：索引更新

任何影响索引内容或过滤的领域提交必须同时写入索引更新任务。包括：

- 创建、编辑、归档、删除、恢复和永久删除记录；
- 清单项目增删改；
- 分类/标签重命名、删除、合并；
- 存放位置、敏感状态和附件文件名变化；
- 恢复、导入、迁移或同步批量变化。

任务按 `(entityId, targetRevision)` 幂等；旧 revision 任务不得覆盖新索引。

### SRCH-081：索引版本

索引保存 `indexSchemaVersion` 和 `normalizationVersion`。任一改变时：

- 标记旧索引不可作为完整结果；
- 从权威数据分页重建；
- 重建期间允许旧索引只读搜索并对新修改做补偿，或清楚显示部分结果；
- 完成后原子切换新索引；
- 索引失败不修改领域数据。

### SRCH-082：完整性检查

至少检查：

- 每个可搜索根记录恰好一份当前 revision 文档；
- archived/trashed 域与根状态一致；
- 已删除子项不在命中内容；
- 敏感预览标志与根记录一致；
- 索引引用的附件和分类标签存在。

发现不一致时重建受影响记录；比例超过 1% 时触发全量重建和诊断。

## 10. 隐私与安全

### SRCH-090：本地保护

- 搜索索引与领域数据库使用同等级静态加密；
- App 未解锁时不初始化可返回内容的搜索会话；
- 系统键盘、剪贴板和截图策略按安全规范处理，敏感搜索不进入系统最近活动；
- 后台缩略图不得显示查询或结果。

### SRCH-091：日志和遥测

不得记录或上传：

- 原始查询文本或规范化 token；
- 命中的标题、正文、标签、位置或文件名；
- 单次敏感结果 ID。

可以记录经过批准的非内容指标：查询是否为空、token 数粗分桶、结果数分桶、耗时、索引版本、错误码和用户是否打开结果。小样本和事件 Schema 规则仍适用。

### SRCH-092：智能上下文

智能功能不能直接查询搜索索引或接收用户所有匹配结果。PR-408 上线后流程必须是：用户输入本地查询 → 应用显示有权限且不禁用 AI 的结果 → 用户明确选择 → 应用最小化字段 → 确认发送范围。

## 11. 性能与分页

### SRCH-100：结果分页

- 首批最多 30 条，后续每页最多 50 条；
- 使用稳定游标，不用会因插入导致重复/遗漏的裸 offset 作为跨页契约；
- 查询或筛选改变后废弃旧游标；
- 列表只加载展示所需字段，正文片段按匹配结果生成；
- 滚动加载失败保留已有结果并允许重试。

### SRCH-101：性能门槛

直接采用 QR-011 和 QR-020：设计容量下首批结果 P95 ≤ 400 毫秒。测量分解为规范化、索引查询、权限/生命周期过滤和片段生成；不能用减少索引范围绕过正确性。
