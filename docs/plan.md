## 阶段 4：Web 与 Android 打磨

目标：Web 和 Android 真机可以每天稳定使用，不依赖开发环境。

**日常使用**

- [ ] Android 打一个不依赖 Metro 的 release 包，构建时用 `LIFE_BOOK_API_URL` 指向电脑的局域网地址，并允许局域网内的 HTTP 访问
- [ ] 服务端监听局域网地址，提供一个不带 `watch` 的启动命令，方便长期开着
- [ ] 在 Web 和 Android 上连续使用一周，问题记到 GitHub Issues

**Android 提醒可靠性**

- [ ] 应用被划掉、锁屏或手机重启后，提醒仍按时到达（重点验证小米的省电和自启动限制）
- [ ] 检查精确闹钟权限（Android 14 起默认不授予），没有授权时在“我的”里说明影响并引导开启
- [ ] 应用图标、启动图和通知小图标

**体验问题（真机走查发现）**

- [ ] 表单有未保存的修改时，返回前先确认（Web 和 Android）
- [ ] 生活簿列表里的“下次”考虑改期和已处理的实例，与详情页一致
- [ ] 手机上修改清单项目的名称、分组、数量和单位
- [ ] 详情页“最近”：改期到某天后，那天原本的一次也要显示

**工程**

- [ ] Web 端到端测试放进仓库，并在 CI 中运行
- [ ] 开发时手机热更新不稳定：查明原因或在开发说明里写清楚

**完成标准**：在 Web 和 Android 上连续使用一周；应用不在前台时，Android 上的提醒也按时到达；在一端修改，另一端刷新后可以看到。

## 工作方式

- 直接在 `main` 上开发（见 [D-021](decisions.md)）：提交前在本地跑 `pnpm verify`，推送后 CI 再跑一遍，失败了优先修复。
- 提交信息用 Conventional Commits（如 `feat(server): add records api`），一个提交是一个完整的小改动。
- 业务规则先在 `core` 写单测，再写实现。
- 行为、表结构或接口变化时，同步更新 `docs/` 中对应的文档；重要取舍追加到 [决策记录](decisions.md)。
