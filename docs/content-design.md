# 生活有谱内容设计规范

> 项目代号：`life-book` · 版本：v1.0 · 更新日期：2026-07-26 · 状态：产品文案基线
>
> 权威范围：界面语言、术语、操作标签、状态与错误、空状态、权限说明、通知、智能、数据安全、同步和家庭协作文案
>
> 不负责：法律条款全文、业务规则、页面布局、营销活动和具体本地化文件格式
>
> 依赖文档：[品牌命名](brand-name.md)、[术语表](glossary.md)、[页面规格](screen-specifications.md)、[用户流程](user-flows.md)、[提醒规范](reminders-and-notifications.md)、[智能创建契约](ai-creation-contract.md)、[数据生命周期](data-lifecycle.md)、[账号与同步](account-and-sync.md)、[家庭共享](family-sharing.md)

本规范的简体中文是源语言基线。代码使用稳定 content key，不把完整中文当自动化测试标识；其他语言以同一意图、风险和信息层级本地化，不逐字硬译。

## 1. 品牌声音

### CONTENT-001：温和、可靠、清楚

| 要做到 | 示例 | 避免 |
| --- | --- | --- |
| 说明下一步 | “已经保存在本机，联网后会继续同步。” | “同步异常！” |
| 描述事实 | “提醒时间已经过去，请换一个时间。” | “你设置错了。” |
| 给用户选择 | “继续编辑 / 放弃更改” | “确定 / 取消”用于所有场景 |
| 承认边界 | “系统勿扰可能影响通知展示。” | “保证准时响铃。” |
| 减少压力 | “今天还有 2 件事可以看看。” | “你落后了 2 项。” |

不使用“高效人生、自律、打败拖延、清零、连续打卡失败”等绩效或羞耻语言。成功反馈克制，不使用彩带、连续庆祝或夸张拟人。

### CONTENT-002：人称和语态

- 默认省略“您”，直接说动作和结果；需要责任边界时用“你”；
- 产品自称“生活有谱”，不自称“小助手”“管家”或“我们已经替你决定”；
- 错误描述系统状态，不把责任推给用户；
- 家庭操作明确 actor：“林青勾选了 2 个项目”，不用模糊被动语态；
- 隐私说明明确主体：“本次文字会发送给智能服务”，不用“可能用于优化体验”掩盖处理。

### CONTENT-003：一句只承担一个任务

标题说结果或问题，正文解释影响，按钮给出选择。不要在一个长句同时塞入风险、恢复、权限和营销。正文一般不超过 3 个短段；复杂范围使用项目列表。

## 2. 术语和命名

### CONTENT-010：界面标准词

| 概念 | 界面用词 | 不使用 |
| --- | --- | --- |
| 五类总称 | 记录 / 生活记录 | 任务（泛称）、条目（用户文案） |
| recurring_item | 重复事项 | 重复日常（仅传播可用） |
| checklist | 清单 | 任务列表 |
| memo | 备忘 | 备忘任务 |
| important_date | 重要日期 | 日期任务 |
| household_item | 家庭物品 | 家庭共享物品（未必共享） |
| attention_item | 关注项 / 今天要看的内容 | 待办（泛称） |
| archive | 归档 | 完成、删除 |
| trash | 移到回收站 / 删除 | 永久删除 |
| purge | 永久删除 | 清理、移除（单独使用） |
| pinned | 置顶 | 收藏 |
| reminder | 提醒 | 推送（泛指） |
| system notification | 系统通知 | 提醒计划 |
| snooze | 稍后提醒 | 推迟事项 |
| family owner | 家庭创建者 | Owner、管理员（首期） |
| family member | 普通成员 / 家庭成员 | 子账号、访客 |

内部代码名不直接暴露。`owner` 在 UI 统一显示“家庭创建者”；`member` 根据上下文显示“普通成员”或“家庭成员”。

### CONTENT-011：动作动词

| 结果 | 推荐按钮 |
| --- | --- |
| 新建 | 创建重复事项 / 创建清单 / 保存备忘 |
| 修改 | 保存修改 |
| 普通删除 | 移到回收站 |
| 不可恢复删除 | 永久删除 |
| 全本机擦除 | 清除本机数据 |
| 退出 | 保留本机副本并退出 / 清除本机副本并退出 |
| 家庭共享 | 移到“{familyName}” |
| 家庭独立副本 | 复制到个人空间 |
| 智能结果写入 | 确认创建 |
| 重新调用模型 | 重新整理 |

不要用同一个“保存”同时表示创建备份、保存表单、上传和同步；让对象或结果可见。

### CONTENT-012：状态用词

- 重复事项：待处理、已完成、已跳过、已逾期；
- 清单：进行中、已完成、已逾期（有截止且适用）；
- 备忘/重要日期：不使用完成、跳过、逾期；过时未确认备忘提醒叫“待查看”；
- 家庭物品：库存充足、需要补货；规则文案用“当前数量不多于最低库存”；
- 提醒：已安排、等待安排、已知道、已稍后、已取消、已过期、安排失败；不声称“已送达”；
- 同步：已保存在本机、等待同步、正在同步、已同步、需要你选择、同步已暂停；
- 附件：正在处理、可查看、文件缺失、文件损坏。

## 3. 数字、日期和变量

### CONTENT-020：日期时间

- 普通近距离展示可用“今天 21:00”“明天 09:00”，详情同时可读完整日期；
- 高风险确认、跨时区、备份/删除/邀请到期始终显示绝对日期、时刻和必要时区；
- “7 天后”后面补“2026 年 8 月 2 日”，不能只给相对时间；
- 全天明确“全天”，不显示虚构 00:00；
- 时区只在会影响理解时显示友好名称和 IANA 标识详情；
- 年龄/周年由 counterDisplay 和 startYear 派生，缺年份不显示“0 岁/第 0 年”。

### CONTENT-021：数量和单位

- 使用 ExactDecimal 原值和地区小数符号，不二进制舍入；
- 数量与单位之间按语言排版规则留空，如“2.5 千克”；
- 库存变化显示“3 → 1（使用 2）”；
- 低库存统一：“剩余 {current} {unit}，最低库存 {threshold}”；
- 不写“少于 {threshold} 才提醒”，因为相等也属于低库存；
- 无法确定最小步长时购买建议标“建议”，不说“应该买”。

### CONTENT-022：占位符安全

content key 的变量使用受控类型：`safeTitle`、`localDateTime`、`count`、`unit`、`spaceDisplayName`、`memberDisplayName`、`diagnosticId`。所有文本变量按纯文本转义；标题为空/敏感/未解锁时使用类型级替代，不把 `null`、ID 或路径显示给用户。

复数、量词、性别和语序由本地化系统处理，不能在代码拼接“还有 ”+N+“ 天”。

## 4. 页面标题、按钮和反馈

### CONTENT-030：标题层级

- 导航标题优先对象类型/功能，如“创建清单”“数据与存储”；
- 详情页标题可以是用户标题，但导航栏截断后主体仍提供完整可访问名称；
- 弹窗标题明确问题：“要放弃这些更改吗？”“永久删除这条备忘？”；
- 加载标题说过程：“正在验证备份”，不使用无信息“处理中”；
- 成功标题说已完成事实：“备份已创建并验证”。

### CONTENT-031：主次动作

- 主动作是用户进入页面的预期结果；取消/返回不使用危险色；
- 破坏性动作标签必须准确，默认焦点放安全选择；
- 三个以上选择使用列表说明各自后果，不堆成三按钮弹窗；
- 禁用按钮旁提供可发现原因；不要让用户点击后才知道缺字段；
- 进行中改为“正在保存…”并防重复，完成后不留下可再次点击的按钮。

### CONTENT-032：即时反馈

| 事件 | 推荐反馈 |
| --- | --- |
| 普通保存 | “修改已保存” |
| P1 离线保存 | “已保存在本机，联网后会同步” |
| 局部提醒失败 | “记录已保存，提醒还没有安排好”+“检查提醒” |
| 归档 | “已归档”+“撤销” |
| 移到回收站 | “已移到回收站，30 天内可以恢复”+“撤销” |
| 复制 | “已复制为一条新记录”+“查看” |
| 重复幂等动作 | “已经完成”/“已经知道了”而非错误 |

Toast 不承载不可逆风险、长说明或唯一恢复动作；重要状态在页面中可再次找到。

## 5. 空状态与渐进引导

### CONTENT-040：空状态公式

```text
发生了什么（不评判）
+ 为什么 / 当前筛选
+ 一个真实下一步
```

示例：

- 今天空：“今天暂时没有需要你处理的内容。” / “想记一件事，可以从下面开始。” / “记一件事”；
- 生活簿空：“这里还没有生活记录。” / “重复事项、清单、备忘、重要日期和家庭物品都会出现在这里。” / “创建第一条记录”；
- 筛选空：“没有符合这些条件的记录。” / “清除筛选”；
- 低库存空：“目前没有需要补货的物品。”；
- 回收站空：“回收站是空的。移到这里的记录会保留 30 天。”；
- 同步冲突空：“目前没有需要你选择的同步内容。”。

不使用虚假示例记录、庆祝“清零”或暗示用户必须填满。

### CONTENT-041：首次场景示例

智能输入示例轮换且可访问：

- “每周日晚上九点提醒我整理客厅”；
- “做一份三天出差清单”；
- “记下路由器型号 AX3000”；
- “妈妈生日是 8 月 12 日”；
- “家里还有 2 支牙膏，最低留 1 支”。

示例不自动提交、不成为输入历史，也不含医疗/紧急承诺。

## 6. 校验和错误

### CONTENT-050：字段错误结构

错误写“哪里 + 为什么 + 怎么改”：

- “标题不能为空”；
- “日期不存在，请换一个日期”；
- “数量最多保留 3 位小数”；
- “使用后会变成负数。请减少数量，或选择‘调整’记录实际库存”；
- “结束日期早于第一次发生日期”；
- “这个重复方式当前还不支持。可以换成指定日期，或改用备忘”。

不用“非法、无效参数、400、Schema failed”。

### CONTENT-051：服务错误结构

| 原因 | 标题 | 正文方向 | 动作 |
| --- | --- | --- | --- |
| 离线 | 当前没有网络 | 已保存在本机/联网后可继续 | 稍后再试 |
| 暂时服务错误 | 现在还不能完成 | 内容和本机数据仍在 | 重试 / 手动路径 |
| 认证过期 | 需要重新登录 | 本机数据仍保留 | 重新登录 |
| 权限失效 | 你已不能访问这个家庭 | 本机共享副本将按规则清理 | 返回个人空间 |
| 版本过旧 | 更新后才能继续 | 未知数据保持只读 | 更新 App / 导出 |
| 完整性错误 | 为保护数据，已暂停修改 | 不尝试覆盖或清空 | 查看恢复选项 |

诊断 ID 放“技术详情”中，可复制；不要展示账号、路径、标题、token 或供应商响应。

### CONTENT-052：冲突

- 标题：“这处内容在另一台设备上也改过”；
- 列标签：“这台设备上的版本 / 已同步的版本”；不用“你的 / 对方的”在同账号场景造成混乱；
- 家庭可显示成员：“林青在另一台设备上修改”；
- 时间只能辅助，不把设备时间晚者标“最新”；
- 动作：“保留这台设备的内容 / 保留已同步内容 / 合并后保存”；
- 墓碑/失权：“这条记录已经被永久删除，不能恢复旧修改”。

## 7. 权限前置说明

### CONTENT-060：固定信息结构

1. 权限名和当前动作；
2. 能带来什么；
3. 拒绝后什么仍可用；
4. 何时使用/是否上传；
5. “继续 / 暂不”。

### CONTENT-061：权限基线文案

| 权限 | 标题 | 说明基线 |
| --- | --- | --- |
| 系统通知 | 在你设定的时间提醒 | 允许后，生活有谱会把你明确设置的提醒交给系统。暂不允许也能保存记录，并在 App 内查看。 |
| Android 精确提醒 | 尽量按准确时刻提醒 | 允许精确提醒后，系统更可能按设定时刻安排；不允许时会使用近似提醒，并显示当前状态。 |
| 照片/文件 | 选择要添加的文件 | 只处理你这次选择的内容；取消或拒绝不影响其他字段。 |
| 相机 | 拍摄这一次内容 | 只在你主动拍摄时使用；可改从相册选择或手动输入。 |
| 麦克风 | 把这次录音转成文字 | 只在你主动开始后录音；转写文字会先给你确认。 |
| 生物识别 | 用设备认证解锁生活内容 | 生物识别只用于本机访问门禁；本地数据仍单独加密。 |

不能说“必须允许”“永不错过”“完全安全”。系统对话框已拒绝时按钮写“打开系统设置”，不写“再次允许”。

## 8. 提醒和系统通知文案

### CONTENT-070：内容模式

| 模式 | 标题 | 正文 |
| --- | --- | --- |
| 完整内容 | 经安全截断的记录标题 | 来源适配时间/状态；不含完整正文、数量历史或附件名。 |
| 只显示标题 | 记录标题 | “打开生活有谱查看详情” |
| 完全隐藏 | “生活有谱提醒” | “有一件生活小事该看看了。” |

sensitive 在 P0 始终使用完全隐藏；变量缺失时也回退更严格模式。截断按码点/字素安全处理，不因标题长度泄露正文。

### CONTENT-071：来源模板

| 来源 | 完整内容正文示例 | 动作标签 |
| --- | --- | --- |
| 重复事项 | “计划在 {time}” / 已过时“原计划 {dateTime}” | 完成、跳过、稍后、打开 |
| 清单 | “截止时间到了”或“将在 {relativeTime} 截止” | 打开、稍后 |
| 备忘 | “到了你设定的提醒时间” | 知道了、稍后、打开 |
| 重要日期 | “还有 {days} 天” / “就是今天” / “回顾这一天” | 知道了、稍后、打开 |
| 低库存 | “剩余 {current} {unit}，建议补货” | 加入采购清单、知道了、打开 |

锁屏空间不足时动作可以减少，但语义不能改变；清单不出现“一键完成”。系统通知被清除不显示“已处理”。

### CONTENT-072：可靠性说明

推荐设置说明：

> 已成功安排的提醒可以离线工作。系统勿扰、通知摘要、权限、设备关机和省电设置可能影响实际展示时间；生活有谱会在每次获得运行机会时检查并补齐未来提醒。

Android 近似状态：

> 目前使用近似提醒，系统可能在设定时刻附近展示。你可以在系统设置中允许精确提醒。

不要写“准时送达、一定会响、绕过勿扰”。

## 9. 智能创建文案

### CONTENT-080：入口与称呼

用户界面优先说“帮我整理”“智能整理”“草稿”，不说“AI 自动执行”“智能管家”。“一句话创建”可以作功能名，但按钮结果仍是草稿确认。

### CONTENT-081：首次数据说明

主说明固定意图：

> 本次文字会发送给智能服务进行整理。默认不会发送生活簿中的其他记录；确认前不会写入生活记录数据库。你也可以随时改用手动创建。

详情列实际供应商、处理地区、可能留存和隐私链接。动作：“同意并继续 / 改用手动”。供应商或用途变化重新说明，不能用“继续使用即同意”。

### CONTENT-082：来源标签

| 代码 | 用户标签 | 说明 |
| --- | --- | --- |
| explicit | 你在描述中写了 | 可在详情说明原文位置，但不保存原文范围。 |
| inferred | 根据描述推测 | “请确认是否合适”。 |
| default | 系统建议 | 说明具体默认，如“使用你的当前时区”。 |
| confirmed_edit | 你已修改 | 默认不再强调模型来源。 |

不用“置信度 87%”“AI 认为”；来源不是概率。

### CONTENT-083：智能结果与错误

| 状态 | 用户语言 |
| --- | --- |
| clarification_required | “还需要确认一件事”+唯一问题 |
| unrecognized | “还没能确定要记成哪一种” |
| multiple_intents | “这段话里像是有几件不同的事” |
| unsupported | “这个做法当前还不支持”+最接近手动路径 |
| content_refused | “这次不能使用智能整理，你仍可以手动保存” |
| quota | “本期智能整理额度已用完”+手动入口 |
| timeout/provider | “智能整理暂时没有完成，输入还在这里” |
| old contract | “更新 App 后才能使用这次智能整理” |

不透露安全规则、隐藏提示或供应商原文，不把拒绝等同于用户内容不能本地保存。

## 10. 数据、备份和删除文案

### CONTENT-090：加密备份

- 标题：“创建加密备份”；
- 口令说明：“这个口令只由你保管。忘记后，生活有谱无法替你找回或恢复这份备份。”；
- 范围：“包含生活记录、附件、回收站和必要设置；不包含设备密钥、账号令牌或自带 Key。”；
- 成功：“备份已创建并验证”+时间/大小/格式；
- 错误口令：“口令不正确，或文件无法验证。当前数据没有改变。”；
- 损坏：“这份备份没有通过完整性检查。当前数据没有改变。”。

不要用“云备份”称呼用户保存到系统文件/网盘的 `.lifebook`。

### CONTENT-091：整体恢复

确认标题：“用这份备份替换本机数据？”

正文必须包含：备份时间/范围、当前数据将整体替换、不合并、先验证再切换、外部副本不受影响。按钮：“替换并恢复 / 取消”。完成：“数据已恢复并检查完成”；失败：“恢复没有完成，原来的数据仍在”。

### CONTENT-092：导出

风险说明：

> 导出文件不会使用生活有谱的备份加密。保存或分享后，请按文件中的内容选择安全位置。

敏感选项明确“包含敏感记录（需要再次解锁）”。不把导出称为可靠备份，除非格式确实可由恢复流程使用。

### CONTENT-093：删除层级

| 操作 | 标题 | 必须说明 |
| --- | --- | --- |
| 移到回收站 | “把这条{type}移到回收站？” | 取消未来提醒、30 天可恢复 |
| 永久删除 | “永久删除这条{type}？” | 子对象/附件、不可恢复、备份副本不受影响 |
| 清空回收站 | “永久删除回收站中的 {count} 条记录？” | 部分失败会报告、不可恢复 |
| 清除本机数据 | “清除这台设备上的生活数据？” | 外部备份/云端不自动删除、新空个人空间 |
| 删除账号 | “计划删除账号？” | 7 天日期、个人/家庭/云备份、保留/清除本机选择 |
| 删除家庭 | “计划删除“{familyName}”？” | 7 天只读、成员、导出机会、不复制到个人 |

危险按钮重复准确动词，不使用“继续”“确认删除”混淆不同层级。

## 11. 同步和账号文案

### CONTENT-100：账号价值

登录入口：

> 不登录也能继续使用本机功能。登录后可以主动开启跨设备同步、云备份和家庭空间。

不要用遮挡页面、倒计时或“数据将丢失”强迫登录。

### CONTENT-101：认领选择

| 选择 | 标题 | 结果摘要 |
| --- | --- | --- |
| 本地有/云空 | 把这台设备上的个人空间同步到账号 | 保持现有记录和 ID，确认后开始上传。 |
| 本地空/云有 | 在这台设备使用已同步的个人空间 | 先下载和验证，再替换当前空空间。 |
| 双方有—合并 | 预览并合并两边数据 | 先处理重复和冲突，不自动按同名合并。 |
| 双方有—云端 | 备份本机后使用云端数据 | 本机当前数据会整体替换。 |
| 仅本机 | 暂不同步这份数据 | 账号保持登录，生活簿只显示当前本机空间。 |

来源账号不符：“这份数据来自另一个账号，不能直接上传到当前账号。”不显示对方邮箱。

### CONTENT-102：同步状态

固定表达：

- “已保存在本机 · 等待同步”；
- “正在同步 {count} 项”；总数未知时“正在同步”；
- “已同步 · {absoluteOrRelativeTime}”；
- “当前离线 · 联网后会继续”；
- “有 {count} 处需要你选择”；
- “需要重新登录 · 本机数据仍在”；
- “同步已暂停，为保护数据暂时不能修改这个空间”。

不说“已上传”代表所有设备已应用，不用绿色勾暗示已有云备份。

### CONTENT-103：退出和设备撤销

退出选择必须完整写出：

- “同步完成后，保留本机副本并退出”；
- “立即保留本机副本并退出（未同步修改只留在这里）”；
- “清除本机副本并退出（云端数据不删除）”；
- “取消”。

撤销设备说明：“这台设备将不能继续访问账号服务。无法保证删除它已经离线保存、导出或截图的内容。”

## 12. 家庭协作文案

### CONTENT-110：空间持续可辨

- 个人空间显示“个人空间”；家庭显示用户名称和“家庭空间”辅助标签；
- 移动、删除、导出和 AI 上下文始终重复当前空间；
- 不只靠颜色区别空间；
- “家庭物品”类型名不因在个人空间中改名，避免误解为已共享。

### CONTENT-111：邀请和加入

邀请分享预览：

> 邀请你加入生活有谱中的一个家庭空间。登录后可以查看家庭名称和共享范围。

加入确认：

> 加入后，你可以查看和编辑这个家庭空间中的全部记录。你的个人空间不会自动共享，也不会自动收到全部家庭提醒。

必须补充：“敏感记录仍对全部家庭成员可见，只会加强通知和解锁保护。”

### CONTENT-112：移入家庭

标题：“把“{safeTitle}”移到“{familyName}”？”

影响摘要按适用展示：

- “{memberCount} 位家庭成员将能查看和编辑”；
- “库存流水 / 清单项目与完成历史 / 周期历史会一起共享”；
- “{attachmentCount} 个附件会一起移动”；
- “个人操作记录不会公开；家庭记录从这次共享开始”；
- “你会默认收到这条记录的提醒，其他成员需要自己订阅”。

按钮“移到家庭空间”；不要写“共享”后实际复制两份。

### CONTENT-113：成员移除和离线边界

> 移除后，这位成员会立即失去服务端访问权限；设备联网后会清理家庭副本和提醒。生活有谱无法撤回已经导出、截图或离线看过的内容。

历史说明：“这位成员创建的家庭记录和操作历史会保留，不会转成你的个人记录。”

### CONTENT-114：所有权和家庭删除

- 转移发起：“对方需要在 24 小时内接受。在此之前，你仍是家庭创建者。”；
- 目标接受：“接受后，你将负责邀请、成员移除、永久删除和家庭删除。”；
- 计划删除：“家庭将在 {absoluteDateTime} 永久删除。等待期间只读，不再发送新的家庭提醒。”；
- 取消：“已取消删除。未来提醒会从现在开始重新安排，不补发已经过去的通知。”。

## 13. 敏感、锁屏和后台

### CONTENT-120：不通过措辞泄露

未解锁/完全隐藏状态不用内容长度、事件种类、家庭名、数量或附件类型暗示敏感事实。统一使用“敏感记录”“生活有谱提醒”“有一项内容需要查看”。可访问名称也使用同一保护，不让读屏越过视觉遮罩。

### CONTENT-121：应用锁失败

- 取消：“内容仍保持锁定”；
- 认证失败：“没有解锁，请再试一次”；
- 系统锁定：“设备认证暂时不可用，请稍后重试或使用设备凭据”；
- 无恢复方式：“无法在这台设备解锁现有数据。可以恢复一份加密备份，或清除本机数据重新开始。”；
- 绝不说“忘记密码？”暗示产品能恢复设备数据密钥。

## 14. 本地化和维护

### CONTENT-130：content key

key 按语义而非页面位置命名，例如：

```text
record.trash.confirm.title
backup.restore.integrity_failed.body
reminder.permission.preprompt.body
sync.status.saved_locally
family.move.visibility_warning
ai.provenance.inferred.label
```

禁止 `screen1_button2`、拼接句子或在代码中复制同一中文。改变 key 语义时新建 key；仅改译文可保留。

### CONTENT-131：变量和长度测试

- 所有 key 声明变量名、类型、是否敏感和缺失回退；
- 用 0/1/2/99/9999、长标题、emoji、RTL、长德语等伪本地化测试；
- 按字素安全截断并给读屏完整/安全替代；
- 按地区处理日期、数字、复数和周起始，不把中文量词写死；
- 按钮不可仅因翻译变长而省略结果动词。

### CONTENT-132：文案评审门槛

新增/改变文案必须检查：

- 术语与 glossary 一致；
- 动作结果与领域规则一致；
- P0/P1/P2 不承诺未交付能力；
- 没有绝对通知、加密、删除或 AI 正确性承诺；
- 敏感内容和变量在锁屏/通知/日志中安全；
- 错误提供恢复路径且不责备；
- 读屏名称不泄露且不依赖图标；
- 法律含义改变时由合规文档和真实运营主体审阅。
