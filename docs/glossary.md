# 生活有谱术语表

> 项目代号：`life-book` · 版本：v1.0 · 更新日期：2026-07-26 · 状态：文档基线  
> 权威范围：产品、设计、工程、测试和运营共同使用的标准术语及代码名  
> 依赖文档：[品牌命名方案](brand-name.md)、[产品决策记录](product-decisions.md)、[文档治理规范](documentation-governance.md)

本文只定义词语的含义，不定义完整业务行为。行为规则由产品功能说明和各专项规范负责。用户界面可以使用更自然的完整句子，但不得改变术语的业务含义。

## 1. 命名层级

| 标准名称 | 代码名 | 定义 | 使用规则 |
| --- | --- | --- | --- |
| 生活有谱 | `LifeBook` | 产品对外中文品牌。 | 正式介绍首次出现时使用全称；界面空间足够时不缩写。 |
| 有谱 | — | “生活有谱”的日常简称。 | 只用于自然文案；商店、法律文本和系统权限说明使用全称。 |
| `life-book` | `life-book` | 仓库、包命名空间和内部项目代号。 | 不作为对外英文品牌。 |
| 生活簿 | `library` | 用户查看和整理全部生活记录的产品化视图。 | 也是 P0 底部导航名称；它不是数据库实体，也不等同于空间。 |
| 空间 | `space` | 一组具有共同所有权和可见范围的数据容器。 | P0 只有默认个人空间；P2 增加家庭空间。 |

层级关系统一为：

```text
本地身份或账号
└── 空间
    └── 生活记录及其子对象

“生活簿”是浏览这些记录的界面视图
```

## 3. 生活记录与五种记录类型

### 3.1 通用概念

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 生活记录 | `record` | 归属于一个空间、可以被浏览和整理的业务对象总称。 |
| 记录类型 | `record_type` | 重复事项、清单、备忘、重要日期或家庭物品之一。记录创建后不得直接改成另一类型。 |
| 记录详情 | `record_detail` | 某类记录特有的数据，与通用记录字段共同组成完整记录。 |
| 关联 | `record_link` | 两条记录之间由用户确认建立的有方向关系，不表示两者生命周期绑定。 |
| 附件 | `attachment` | 与记录关联的图片或文件；二进制内容不属于正文。 |

“记录”是文档中的推荐简称。“事项”只用于重复事项，不作为五种记录的总称；避免使用“任务”作为通用名称。

### 3.2 重复事项

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 重复事项 | `recurring_item` | 按规则周期性产生需要处理实例的生活记录，例如每周换床单。 |
| 重复规则 | `recurrence_rule` | 描述实例如何在日期时间轴上产生的规则。 |
| 周期实例 | `occurrence` | 重复事项在某一次计划日期上的独立执行对象。 |
| 计划时间 | `scheduled_for` | 周期实例预计发生或执行的日期时间；没有具体时间时可以是全天日期。 |
| 完成 | `complete` | 用户确认某个周期实例已经做完。 |
| 跳过 | `skip` | 用户有意识地决定本周期不执行；与完成和未处理不同。 |
| 逾期 | `overdue` | 已经过计划时间或业务截止点，且仍未完成或跳过的可执行对象状态。 |

“重复日常”可以出现在品牌传播文案中；产品规格、界面类型选择器和代码统一使用“重复事项”。

### 3.3 清单

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 清单 | `checklist` | 清单实例的用户界面简称；在需要同时讨论模板时使用完整名称。 |
| 清单模板 | `checklist_template` | 可重复使用、不保存某次完成进度的项目结构。 |
| 清单实例 | `checklist_instance` | 一次具体使用的清单，拥有独立项目状态、可选截止时间和提醒。 |
| 清单分组 | `checklist_group` | 在模板或实例内组织清单项目的可排序容器。 |
| 清单项目 | `checklist_item` | 可以独立勾选、排序和记录数量的最小清单单位。 |
| 清单进度 | `checklist_progress` | 已完成有效项目数与全部有效项目数形成的派生值。 |
| 采购清单 | `shopping_checklist` | 用于记录待购买物品的清单实例，可与家庭物品建立关联。它不是第六类记录。 |

文档单独写“清单”时默认指清单实例；若规则同时适用于模板和实例，必须明确写“清单模板与清单实例”。

### 3.4 备忘

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 备忘 | `memo` | 用于长期保存信息、默认没有完成状态的生活记录。 |
| 正文 | `body` | 备忘的主要文本内容。 |
| 备忘提醒 | `memo_reminder` | 让用户在某时重新看到备忘的提醒；提醒结束不改变备忘生命周期。 |

“备忘事项”可以用于自然介绍，产品类型名统一为“备忘”。备忘不得显示“完成”或“跳过”。

### 3.5 重要日期

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 重要日期 | `important_date` | 表示生日、纪念日、到期日或其他需要记住日期的生活记录。 |
| 日期事件种类 | `date_event_kind` | 生日、纪念日、到期日或其他，决定默认文案但不决定历法和重复方式。 |
| 历法 | `calendar_system` | 公历或后续支持的农历。 |
| 日期重复方式 | `date_recurrence` | 仅一次或每年重复，与历法是两个独立维度。 |
| 日期发生项 | `date_occurrence` | 重要日期在某一年对应的具体日期，用于提醒和“今天”展示。 |
| 起始年份 | `start_year` | 用于计算年龄或周年的可选年份，不改变日期本身。 |

“日期提醒”描述的是能力，不是记录类型；类型名统一为“重要日期”。重要日期本身不使用“完成”“跳过”或“逾期”状态。

### 3.6 家庭物品与库存

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 家庭物品 | `household_item` | 需要记录数量、位置或相关信息的家中物品。名称不表示它已经共享给家庭成员。 |
| 库存 | `stock` | 某个家庭物品当前可用数量的业务概念。 |
| 当前数量 | `current_quantity` | 由有效库存流水计算并校验的当前库存值。 |
| 最低库存 | `low_stock_threshold` | 用户设定的不足判断阈值；当前数量小于或等于它时处于低库存。 |
| 库存流水 | `stock_transaction` | 买入、使用、调整、报废或丢失造成的一次不可变库存变化记录。 |
| 期初库存 | `opening_balance` | 创建家庭物品时记录初始数量的第一条库存流水。 |
| 低库存状态 | `low_stock_state` | 当前数量小于或等于最低库存时的派生状态。 |
| 低库存周期 | `low_stock_episode` | 从进入低库存到补货恢复之间的一段连续状态，用于避免重复通知。 |
| 补货 | `replenish` | 通过买入流水增加库存并可能解除低库存状态。 |

“家庭用品”“家中物品”和“家中存量”可以出现在传播文案中；类型名统一为“家庭物品”。

## 4. 提醒与通知

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 业务时间 | `due_at` / `scheduled_for` | 记录或实例本身发生、执行或截止的时间。 |
| 提醒计划 | `reminder_plan` | 用户或系统定义“何时提醒”的长期规则，可以相对业务时间或使用绝对时间。 |
| 提醒实例 | `reminder_instance` | 提醒计划计算出的某一次具体提醒，拥有独立状态和去重标识。 |
| 系统通知 | `system_notification` | iOS 或 Android 向用户展示提醒实例的一次投递方式。 |
| 应用内提示 | `in_app_alert` | 用户打开 App 后看到的提醒或状态反馈，不依赖系统通知权限。 |
| 通知动作 | `notification_action` | 用户从系统通知直接触发的完成、跳过、稍后提醒、知道了或打开等操作。 |
| 稍后提醒 | `snooze` | 针对一个提醒实例创建新的稍后时间；不修改原记录的业务时间。 |
| 重复催促 | `follow_up_reminder` | 用户明确开启后，在首次提醒未处理时按设定间隔产生的后续提醒。默认关闭。 |
| 通知权限 | `notification_permission` | 操作系统允许 App 展示通知的授权。 |
| 精确提醒权限 | `exact_alarm_permission` | Android 上允许按精确时刻调度部分提醒的特殊权限，与通知权限不同。 |
| 应用静默时段 | `app_quiet_hours` | 产品对非用户明确设定的建议和回顾通知进行抑制的时间段。 |
| 系统勿扰模式 | `system_focus` | 由操作系统控制通知展示的模式；生活有谱不能绕过或承诺控制。 |

统一使用“提醒”表示业务意图，使用“系统通知”表示平台投递。除非特指服务端远程通道，不使用“推送”泛指本地通知。

## 5. 记录整理与生命周期

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 分类 | `category` | 一个空间内由用户维护的单选归类；一条记录最多属于一个分类。 |
| 标签 | `tag` | 一个空间内由用户维护的多选标记；一条记录可以有多个标签。 |
| 置顶 | `pinned` | 让一条记录在适用列表中优先展示的布尔状态。 |
| 归档 | `archived` | 记录仍被保留和可搜索，但不再参与默认活跃视图和未来提醒。 |
| 删除 | `trash` | 将记录移入回收站的可恢复操作，不立即擦除数据。 |
| 回收站 | `trash_bin` | 保存已删除记录及剩余保留时间的视图。 |
| 恢复记录 | `restore_record` | 将回收站中的记录恢复为删除前的非删除状态。 |
| 永久删除 | `purge` | 不可通过产品恢复的删除操作。 |
| 清除本机数据 | `erase_local_data` | 删除本设备中的生活数据并重新建立空的默认个人空间。 |

项目不另设“收藏”状态。需要常用记录优先展示时统一使用“置顶”。“删除空间”只用于 P2 家庭空间；P0 默认个人空间实体始终存在。

## 6. 身份、账号、空间与共享

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 本地身份 | `local_actor` | P0 首次安装时在设备生成的稳定匿名身份，用于所有者和修改人字段，不是账号。 |
| 账号 | `account` | P1 用户主动注册或登录后获得的跨设备身份。 |
| 个人空间 | `personal_space` | 始终属于一个本地身份或账号、默认私密的空间。 |
| 家庭空间 | `family_space` | P2 由成员主动加入并共享记录的空间。 |
| 家庭成员 | `family_member` | 一个账号在家庭空间中的成员关系。 |
| 家庭创建者 | `family_owner` | 创建家庭空间并负责成员及高风险操作的唯一所有者角色。 |
| 普通成员 | `family_member_role` | 可以查看、新建和编辑共享记录的基础角色。 |
| 主动共享 | `explicit_share` | 用户明确将记录创建或移动到家庭空间的行为。加入家庭不构成主动共享。 |
| 操作记录 | `audit_event` | 谁在什么时间对共享或高风险对象执行了什么操作的不可变摘要。 |

P0 中“创建人”和“修改人”指本地身份；登录后才可能映射为账号。不得用设备名称、邮箱或昵称替代稳定标识。

## 7. 数据、备份、导入与同步

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 本地数据 | `local_data` | 保存在 App 私有存储、无需网络即可操作的数据。 |
| 加密备份 | `encrypted_backup` | 用户主动创建、由独立口令保护、可离线保存或分享的版本化备份包。 |
| 恢复 | `restore` | 从本产品加密备份包重建一套完整本地数据；P0 采用验证后整体替换。 |
| 导出 | `export` | 将用户数据生成为便于阅读或迁移的文件；导出文件不自动等同于可恢复备份。 |
| 导入 | `import` | 将外部结构化数据经过预览和映射后并入现有数据；属于 P1。 |
| 云备份 | `cloud_backup` | 由账号触发、保存在服务端的备份能力，不等同于实时同步。 |
| 同步 | `sync` | 在设备和服务端间持续交换增量变更，使多个副本收敛。 |
| 冲突 | `sync_conflict` | 两个副本基于同一旧版本产生无法安全自动合并的修改。 |
| 删除墓碑 | `tombstone` | 同步系统中保留的删除标记，用于阻止离线设备复活已删除对象。 |
| 数据迁移 | `migration` | 将旧结构或旧格式确定性转换为新版本的过程。 |

“恢复”不称为“导入”。“分享清单”是把单个清单交给他人查看或使用，“家庭共享”是权限能力，“导出”是生成文件，三者不得混用。

## 8. 隐私与智能能力

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 敏感内容 | `sensitive` | 用户标记为需要更严格展示、通知和数据使用保护的记录或附件。 |
| 禁止用于智能功能 | `ai_access_disabled` | 阻止该记录内容进入任何模型请求的独立设置。敏感不自动等同于该设置，但默认建议开启。 |
| 应用锁 | `app_lock` | 使用生物识别或设备凭据阻止他人进入 App 的会话门禁。 |
| 设备数据加密 | `device_encryption` | 对本地数据库和附件静态数据的加密保护，与应用锁是不同控制。 |
| 智能创建 | `intelligent_creation` | 将用户本次自然语言输入转换成一条或多条结构化记录草稿的能力。 |
| 原始输入 | `raw_input` | 用户本次提交给智能创建的文字或后续语音转写内容。 |
| 草稿 | `record_draft` | 尚未写入生活簿、可以校验和修改的结构化候选记录。 |
| 建议字段 | `suggested_field` | 模型推断或采用默认值、并非用户明确提供的字段。 |
| 追问 | `clarification` | 为解决影响正确创建的关键歧义而向用户提出的问题。 |
| 程序校验 | `deterministic_validation` | 不依赖模型判断，对字段类型、范围和业务不变量进行的确定性检查。 |
| 模型供应商 | `model_provider` | 提供模型推理能力的外部服务，例如 GPT 或千问对应服务。 |
| 供应商适配器 | `provider_adapter` | 把统一请求转换为供应商请求，并把结果转换为统一草稿契约的模块。 |
| 内置智能服务 | `managed_ai` | 由生活有谱服务端持有供应商凭据并为普通用户提供的智能创建能力。 |
| 自带 API Key | `byok` | P1 高级用户在设备上配置并自行承担费用的供应商凭据。 |

智能创建不是聊天模块。模型只能提出草稿或修改建议，不直接访问数据库，也不在用户确认前创建、修改或删除生活记录。

## 9. 时间语义

以下是内部规范术语，通常不直接展示给普通用户：

| 标准名称 | 代码名 | 定义 |
| --- | --- | --- |
| 全天日期 | `all_day_date` | 只有日历日期、没有时刻的值。 |
| 浮动本地时间 | `floating_local_time` | 随用户所在时区保持相同钟表时间的日期时间，例如“每天晚上 9 点”。 |
| 时区绑定时间 | `zoned_date_time` | 绑定某个 IANA 时区规则的日期时间，例如“东京时间上午 9 点”。 |
| 绝对时刻 | `instant` | 时间轴上不随显示时区改变的唯一时刻。 |
| IANA 时区 | `time_zone_id` | 例如 `Asia/Shanghai` 的时区标识，不使用固定 UTC 偏移替代。 |
| 周起始日 | `week_start` | 日历和按周规则使用的一周第一天，由用户设置或地区默认决定。 |

不得只用“时间戳”描述所有时间。业务日期、用户看到的钟表时间、时区规则和绝对时刻必须按场景保存。

## 10. 交付阶段

| 标准名称 | 定义 |
| --- | --- |
| P0 | 首个可用版本，建立记录、提醒、查找、备份和恢复闭环。 |
| P1 | 增强版本，加入账号、同步和更高效输入等能力。 |
| P2 | 扩展版本，加入家庭协作和建立在成熟数据上的能力。 |
| 发布门槛 | 某阶段对外发布前必须全部通过的结果条件。 |
| 纵向切片 | 从页面、领域、存储到测试形成可运行闭环的一小段功能。 |

“第一版”“首发版本”和“MVP”容易产生范围歧义。规范文档统一使用 P0、P1、P2；传播材料需要自然表达时可以写“首个可用版本（P0）”。

## 11. 推荐与避免的表达

| 推荐 | 避免 | 原因 |
| --- | --- | --- |
| 重复事项 | 任务、重复日常（规格中） | 避免绩效工具语气并统一类型名。 |
| 重要日期 | 日期提醒（作为类型名） | 日期与提醒是不同概念。 |
| 提醒 / 系统通知 | 推送（泛指一切） | 区分业务意图与平台投递。 |
| 置顶 | 收藏、星标 | 当前只有一个优先展示状态。 |
| 删除 / 永久删除 | 删除（同时表示两者） | 明确能否恢复。 |
| 清除本机数据 | 删除个人空间 | 默认个人空间始终存在。 |
| 恢复 | 导入备份 | P0 恢复与 P1 通用导入是不同流程。 |
| 系统建议 | AI 猜测 | 温和且说明来源。 |
| 暂时无法使用智能整理 | AI 失败 | 面向用户说明结果而不是内部技术。 |
