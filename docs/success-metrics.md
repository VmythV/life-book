# 生活有谱成功指标与测量口径

> 项目代号：`life-book` · 版本：v1.0 · 更新日期：2026-07-26 · 状态：指标基线
>
> 权威范围：产品指标定义、公式、观察窗口、初始目标和质量护栏
>
> 不负责：遥测事件字段、第三方分析工具和数据采集实现
>
> 依赖文档：[产品需求基线](product-features.md)、[质量属性基线](quality-attributes.md)、[产品假设与验证计划](product-validation.md)

指标用于回答产品是否减少了用户的记忆负担，不能把生活有谱变成追求打卡率的绩效工具。所有目标都是首轮验证基线；只有质量与安全门槛直接阻断发布，产品指标用于学习和决策，不能根据单个数字自动惩罚用户或扩大采集范围。

## 1. 指标原则

1. **先看闭环，不看记录数量**：创建很多但从未再次出现的记录不代表价值。
2. **区分产品可控与平台不可控**：只能准确测量是否计算并交给系统调度，不能声称知道每条系统通知是否被用户真正看到。
3. **不采集内容**：标题、正文、清单项目、物品名、位置、附件、精确业务日期和原始智能输入不进入产品分析。
4. **按类型分层**：总体平均不得掩盖某一记录类型、平台或提醒来源的严重失败。
5. **样本口径透明**：每个比例必须说明分母、观察窗口、是否只包含授权遥测的安装。
6. **定量与定性并用**：留存、完成率必须与访谈、可用性问题和支持反馈一起判断。
7. **不制造压力**：内部可以观察使用行为，界面不默认向用户展示完成率、连续天数或比较排名。

## 2. 基础口径

| 名称 | 定义 |
| --- | --- |
| 有效安装 | 完成首次启动、生成本地身份且不是自动化测试或已知内部机器人流量的安装。 |
| 可测安装 | 在适用法律与用户选择下允许发送产品分析事件的有效安装。 |
| 活跃日 | 用户主动打开 App，并进行查看、创建、搜索、处理或设置操作的自然日；纯后台任务不计。 |
| 活跃周 | 一个滚动 7 日窗口内至少有 2 个活跃日。 |
| 真实记录 | 用户手动保存或确认智能草稿后创建的生活记录；不含系统模板、恢复、导入、自动测试或未确认草稿。 |
| 首次会话 | 首次启动到 App 进入后台超过 30 分钟、被关闭或跨自然日为止。 |
| 重新出现 | 记录或其关注项在创建后的另一个时间点通过今天、系统通知或主动搜索被打开。 |
| 有效处理 | 执行符合来源语义的操作，例如完成/跳过周期实例、勾选清单、知道了、稍后提醒、加入采购清单或打开详情。 |
| 闭环用户 | 在 7 日窗口内至少有一条早先创建的记录重新出现，并被打开或有效处理的用户。 |
| 测试构建 | 明确标记为开发、自动化、演示或内部压测的构建，不进入外部产品指标。 |

P0 没有账号，统计主体是随机安装标识。不得尝试通过设备指纹把卸载重装或多设备强行合并成一个人。P1 登录后，历史匿名指标不得在没有明确说明的情况下回溯绑定账号。

## 3. 核心成功指标

### MET-001：每周闭环用户数

**定义**：最近 7 日内满足“闭环用户”的去重可测安装数。

```text
MET-001 = count(distinct installation_id where closed_loop = true in rolling 7 days)
```

这是产品的北极星指标。它要求记录先被保存，再在合适场景重新出现并被使用，比单纯创建量更接近“有着落”。

初始判断：公开测试期间应连续四周增长，且增长不能以通知数量、隐私关闭率或崩溃率恶化为代价。样本不足时不设绝对人数门槛。

### MET-002：7 日闭环率

**分母**：某日首次创建真实记录的可测安装。

**分子**：随后 7×24 小时内至少完成一次该记录或其派生关注项“重新出现 + 打开/有效处理”的安装。

```text
MET-002 = 7 日内形成闭环的首次创建安装数 / 首次创建安装数
```

封闭测试初始目标：≥ 40%。按首次记录类型、是否智能创建和平台分层观察。

### MET-003：四周持续价值率

**分母**：某周首次形成闭环的可测安装。

**分子**：第 4 个自然周仍形成至少一次闭环的安装。

初始目标：≥ 20%。它是长期价值信号，不作为 P0 单次发布阻断门槛。

## 4. 首次使用与激活

### MET-010：首次会话真实记录创建率

```text
完成至少一条真实记录的首次会话 / 全部有效首次会话
```

公开测试初始目标：≥ 60%。同时观察退出发生在输入前、权限说明、表单、智能等待还是确认页。

### MET-011：一分钟内开始创建率

**分母**：有效首次会话。

**分子**：首次启动可操作后 60 秒内开始输入一句话或打开一种手动创建表单的会话。

初始目标：≥ 80%。开始不等于成功，必须与 MET-010 一起看。

### MET-012：首次记录完成时间

从首屏可操作到第一条真实记录提交成功的时间，分别报告 P50、P75 和 P90，并按智能与手动路径分层。

初始目标：

- 全体创建成功者 P50 ≤ 60 秒；
- 简单智能输入创建成功者 P50 ≤ 45 秒；
- 不以减少确认步骤换取更短时间。

### MET-013：权限拒绝后任务继续率

**分母**：在创建流程中拒绝通知或图片权限的会话。

**分子**：拒绝后仍保存记录或返回可用手动路径的会话。

质量目标：≥ 95%；任何因权限拒绝导致数据丢失的缺陷都阻断发布。

### MET-014：创建后结果理解率

通过可用性测试提问“刚才创建了什么、什么时候会出现”，无需引导且两个答案都正确的参与者比例。

目标：≥ 90%。该指标依赖研究，不通过行为遥测猜测理解。

## 5. 记录、模板与库存价值

### MET-020：记录类型首次采用分布

统计首次 7 日内各记录类型至少创建过一次的可测安装比例。该指标没有单一目标，用于验证五种类型是否都被理解；不得因为某类型使用量低就自动移除，必须结合目标人群和定性证据。

### MET-021：清单模板复用率

**分母**：创建或保存过至少一个清单模板、且观察满 28 日的安装。

**分子**：从同一模板创建至少两个不同清单实例的安装。

封闭测试初始目标：≥ 30%。系统内置模板与用户自建模板分别观察。

### MET-022：清单独立性错误率

模板因实例勾选或编辑而被意外改变的次数 / 从模板创建实例次数。

质量门槛：0。它通过一致性检查和缺陷报告测量，不需要上传清单内容。

### MET-023：库存持续维护率

**分母**：首次创建家庭物品并观察满 14 日的安装。

**分子**：14 日内在至少两个不同日期为任一家庭物品新增有效库存流水的安装。

封闭测试初始目标：≥ 30%。按是否进入低库存和物品数量分层，不能采集物品名。

### MET-024：低库存转采购率

进入低库存周期后 7 日内，通过低库存卡片或物品详情加入采购清单的低库存周期数 / 全部可测低库存周期数。

初始观察值，不预设上线门槛；重点比较重复加入、误触和补货后状态是否正确。

### MET-025：搜索成功代理

**分母**：发起本地搜索的会话。

**分子**：搜索后 60 秒内打开一个结果，且没有立即返回继续修改查询超过两次的会话。

初始目标：≥ 70%。这是代理指标，不能证明用户找到了正确内容；需要配合可用性测试。

## 6. 今天与提醒

### MET-030：今天关注项处理率

按来源类型统计，当日展示的可操作关注项中，在用户所在自然日结束前被打开或有效处理的比例。备忘、日期和低库存不得用“完成率”命名。

### MET-031：提醒调度成功率

```text
成功与系统队列对账的提醒实例 / 需要调度的提醒实例
```

质量目标：≥ 99.9%。分母只包括产品有机会运行并尝试调度的实例，不把系统最终是否展示伪装为可观察结果。

### MET-032：重复通知率

非重复催促配置下，同一去重键被产品重复提交或处理的次数 / 全部提醒实例数。

质量目标：< 0.01%，任何批量重复通知事故都按最高级运行事件处理。

### MET-033：提醒降级可见率

Android 精确提醒不可用、通知权限被拒绝或滚动调度不足时，App 成功显示准确状态和修复入口的受影响实例比例。

质量目标：100%。

### MET-034：通知关闭护栏

获得通知权限的可测安装中，在收到生活有谱通知后的 7 日内关闭系统通知权限或全部产品提醒的比例。

初始护栏：每周 < 5%，且不得因新版本相对基线增加超过 2 个百分点。该指标只能表示相关性，不能断言关闭原因。

### MET-035：默认重复催促开启率

创建提醒时主动开启重复催促的比例，按来源类型观察。没有增长目标；用于确认默认关闭是否满足大多数场景，并监测是否因提醒不可靠被迫开启。

## 7. 智能创建

### MET-040：智能创建尝试率

首次 7 日内至少提交过一次智能输入的可测安装 / 首次 7 日内创建过记录的可测安装。

该指标用于理解入口吸引力，不以最大化为目标；手动创建仍是完整产品能力。

### MET-041：合法草稿率

通过统一 Schema 和确定性业务校验的首次模型响应 / 成功返回的模型响应。

发布门槛遵循 QR-062：≥ 99.5%。按供应商、Schema 版本、记录类型和语言分层，不记录原文。

### MET-042：智能草稿确认率

用户确认保存的合法草稿数 / 展示给用户的合法草稿数。

封闭测试初始目标：≥ 70%。取消、转手动、重新生成和超时分别统计。

### MET-043：关键字段无修正确认率

草稿在记录类型、日期、时间、重复规则、数量和单位等关键字段没有用户修改即确认的比例。

初始目标：≥ 85%，但必须与“建议字段识别率”和严重错误率一起看，不能通过隐藏可编辑字段提高。

### MET-044：单轮追问解决率

**分母**：P0 展示一个关键追问的会话。

**分子**：用户回答后生成合法单条草稿并进入确认页的会话。

初始目标：≥ 80%。仍歧义时正确转手动不计失败，但单独进入降级指标。

### MET-045：智能失败后继续率

智能请求失败、限额、无法识别或校验失败后，用户在同一会话通过重试或手动表单保存记录的比例。

初始目标：≥ 60%；失败时原始输入在当前会话丢失的比例必须为 0。

### MET-046：隐私说明理解率

首次智能创建文案测试中，能准确回答“发送了什么、没有发送什么、何时保存”的参与者比例。

目标：≥ 90%。不能仅用点击“同意”替代理解测量。

## 8. 备份、恢复与数据安全

### MET-050：备份提示转化率

首次显示备份提示后 7 日内成功创建并完成完整性验证的安装数 / 显示提示的可测安装数。

封闭测试初始目标：≥ 20%。关闭提示不视为错误；不得通过频繁提示提高比例。

### MET-051：最近备份覆盖率

拥有至少 10 条活跃记录的可测安装中，最近 30 日内有成功验证备份的比例。

初始观察指标。P1 云备份上线后按本地加密备份和云备份分别计算。

### MET-052：恢复演练成功率

测试环境中从支持格式开始恢复，完成校验、迁移、原子替换和数据一致性检查的次数 / 全部有效恢复尝试。

发布门槛：100%。用户输错口令或主动取消不计有效恢复尝试，但必须验证原数据不变。

### MET-053：静默数据丢失事件

经确认的“产品曾向用户表示保存成功，但数据无法恢复且没有明确错误”的事件数。

质量门槛：0。任何一例立即暂停相关版本发布，启动最高级事故响应。

### MET-054：敏感内容泄露事件

敏感记录标题、正文、附件、原始智能输入或密钥出现在不允许的通知、日志、遥测、崩溃报告或分享预览中的确认事件数。

质量门槛：0。

## 9. 留存与健康护栏

### MET-060：第 7 日回访率

首次创建真实记录的安装中，在第 7 日前后允许窗口内至少有一个活跃日的比例。

初始目标：≥ 25%。窗口统一为首次创建后第 6–8 个自然日。

### MET-061：第 28 日回访率

首次创建真实记录的安装中，在首次创建后第 22–28 日至少有一个活跃日的比例。

初始目标：≥ 12%。必须按核心使用类型分层。

### MET-062：崩溃与无响应护栏

直接引用 QR-033 的崩溃无影响会话率和无响应无影响会话率。本文件不另设不同阈值。

### MET-063：存储与能耗投诉率

公开测试的有效安装中，与异常耗电、后台运行或异常存储增长相关的确认支持事件比例。任何版本相对前一稳定版本显著上升时暂停扩大灰度。

### MET-064：删除与退出护栏

观察清除本机数据、永久删除和卸载前导出/备份的漏斗，但不得通过增加阻碍阻止用户删除。误删且无法恢复的确认事件为质量缺陷，而不是正常流失。

## 10. 指标目标的使用

| 类型 | 示例 | 未达到时动作 |
| --- | --- | --- |
| 发布门槛 | 数据丢失为 0、恢复测试 100%、草稿 Schema 合法率 | 阻断发布，修复并回归。 |
| 质量护栏 | 重复通知率、通知关闭率、崩溃率 | 暂停灰度或关闭相关功能开关。 |
| 产品目标 | 激活、闭环率、模板复用、留存 | 结合研究定位问题，必要时新增产品决策。 |
| 观察指标 | 类型分布、低库存转采购、重复催促开启 | 建立基线，不因单次波动改变范围。 |

不得为了达到指标而：

- 自动创建虚假示例记录；
- 默认开启重复催促；
- 隐藏取消、手动创建、导出或删除入口；
- 采集生活内容或生成设备指纹；
- 把打开通知等同于完成生活事项；
- 用红色警告、羞耻文案或连续天数压力提高处理率。

## 11. 数据质量与报告

- 每个指标报告必须包含定义版本、时间范围、样本量、平台、版本和同意口径；
- 事件丢失、离线积压、时钟异常、重复发送和测试流量必须先校正；
- 小样本不报告可能重新识别个体的细分，默认少于 20 个安装的单元合并或隐藏；
- 指标定义改变后使用新版本，不回写旧数据伪造可比性；
- 发布报告同时列出绝对值、比例、分母和置信范围，不只展示百分比；
- 产品内容不得进入调试指标；需要排查个案时使用用户主动提供的一次性诊断包。

遥测事件、属性白名单、保留期限和同意实现由分析与遥测规范定义。
