# 生活有谱设计系统规范

> 项目代号：`life-book` · 版本：v1.0 · 更新日期：2026-07-26 · 状态：实施基线
>
> 权威范围：视觉原则、设计令牌、主题、排版、间距、图标、组件外观与交互状态、响应式使用和设计验收门槛
>
> 不负责：业务状态机、页面信息归属、最终界面文案、读屏语义细节、品牌商标资产和原生组件具体代码
>
> 依赖文档：[品牌命名](brand-name.md)、[内容语言](content-design.md)、[可访问性](accessibility.md)、[页面规格](screen-specifications.md)、[领域模型](domain-model.md)、[质量属性](quality-attributes.md)

本规范把“温暖、可靠、清楚、不制造自律压力”的品牌方向落实为可实现、可测试和可扩展的界面语言。业务状态仍以领域与专项规范为准；本文件只规定这些状态如何被一致地呈现。

## 1. 设计原则

### DS-001：安静的家用工具

- 内容和下一步优先于装饰；常规页面不使用大面积渐变、玻璃拟态或持续动画；
- 成功反馈克制，不使用彩带、连续打卡火焰、排名、完成率圆环或施压式红色；
- 主色表达可靠和可操作；红/锈红只用于错误、不可逆风险或确已逾期等真实风险，不用于普通进度和催促；
- 留白用于分组和减负，不通过把关键操作藏进手势来换取“简洁”。

### DS-002：语义先于颜色

界面只使用语义令牌和领域组件，不在页面中直接写十六进制颜色、任意字号、阴影或圆角。颜色不得单独表达类型、状态、空间、选中、敏感或错误；必须同时有文字、图标、形状或结构线索，具体可访问性要求见 A11Y-040～A11Y-042。

### DS-003：原生行为优先

- 导航、文本输入、开关、日期时间、系统权限、分享和认证优先采用平台熟悉的行为；
- 共享视觉语言不能覆盖 iOS、Android 或 Web 的输入、焦点、返回和安全区约定；
- 同一组件可以有平台适配外观，但其语义、层级、状态和业务结果必须相同；
- P0 以手机单栏为交付基线；组件从第一版起允许字体放大、横屏和更宽视口重排，不把固定画布尺寸写入业务页面。

### DS-004：隐私状态不能只是蒙层

敏感或锁定内容从数据绑定、可访问性树、系统截图/任务切换预览和自动化快照中一起移除。模糊、骨架或遮罩只能作为可见结果，不能让底层真实文字继续渲染。敏感组件不得通过行高、图片比例、附件图标或占位数量泄露受保护内容。

## 2. 令牌架构与兼容

### DS-010：三层令牌

```text
primitive（原始色值、数值）
    ↓ 仅设计系统内部引用
semantic（surface / text / action / state / spacing / type）
    ↓ 页面与共享组件只引用这一层
component（button.primary.background 等少量组件别名）
```

- primitive 可以随品牌校准变化，产品代码不得直接依赖；
- semantic 名称描述用途而不是颜色，例如 `color.action.primary`，不能命名为 `green700`；
- component 令牌只在一个组件确有跨主题独立调整需求时创建，不复制全部 semantic 令牌；
- 业务数据只能保存 DS-025 定义的稳定注册值，不保存主题色值或 component 令牌。

### DS-011：主题契约

P0 外观只跟随系统，不新增尚未进入 `AppPreferences` 的产品设置。未来若产品需求增加手动外观选择，持久化值才可以定义为 `system | light | dark`，并同步补齐领域、备份和页面规范；设计系统不得先在 UI 私存该值。无论是否提供手动选择，都不能覆盖系统“增强对比度、减少动态效果、粗体文字、字体缩放或 forced colors”等辅助设置。

每个 semantic 令牌必须同时存在 light 与 dark 值。增加令牌时，代码生成和持续集成必须拒绝缺少任一主题的定义。高对比度不是把全部颜色加深，而是由主题适配器提高边界、焦点和状态区分，并允许系统颜色接管 Web forced-colors 场景。

### DS-012：命名与版本

- 令牌使用小写点分层级：`color.text.primary`、`space.4`、`radius.md`、`motion.duration.standard`；
- 令牌包单独使用语义版本；删除或改义属于破坏性变更；
- 令牌重命名至少保留一个公开版本的别名和迁移规则，应用代码不得静默回退到任意值；
- 截图基线、设计稿和实现必须记录使用的令牌包版本；
- 原始值可由构建产物生成 TypeScript、CSS custom properties 和设计工具变量，源注册表只能有一个。

### DS-021：状态颜色

| 状态角色 | Light 前景 / 背景 | Dark 前景 / 背景 | 使用边界 |
| --- | --- | --- | --- |
| `state.neutral` | `#45524C` / `#E9EEEB` | `#C2CCC7` / `#29312E` | 已归档、已跳过、关闭、普通历史。 |
| `state.info` | `#1E568B` / `#E5EFFA` | `#9CCAFF` / `#17334D` | 等待、同步中、已安排、推断信息。 |
| `state.success` | `#1C613C` / `#E2F2E8` | `#89D7A9` / `#163724` | 已保存、已同步、已完成。 |
| `state.warning` | `#754300` / `#FFF0D6` | `#F4C16C` / `#453119` | 逾期、低库存、临近期限、需选择。 |
| `state.danger` | `#96241D` / `#FCE8E6` | `#FFB4AB` / `#482421` | 错误、损坏、永久删除、放宽保护。 |

状态容器始终包含可见文字或安全图标；前景/背景组合均按普通文字 4.5:1 以上选择。`warning` 表示需要注意而非责备；逾期使用下面独立的锈红别名，但不能整卡铺红。`danger` 不用于普通“取消”“返回”或仍可恢复的回收站入口。

业务组件引用独立别名，不在页面中直接判断“某状态等于某种颜色”：

| 业务别名 | 映射 |
| --- | --- |
| `color.attention.upcoming.*` | `state.warning.*`；临近日期/期限。 |
| `color.attention.overdue.foreground/container` | Light `#8B3327 / #FAEAE6`；Dark `#F3B2A7 / #472720`；确已逾期。 |
| `color.inventory.lowStock.*` | `state.warning.*`；同时显示“需要补货”和数量阈值。 |
| `color.sync.pending.*` / `color.sync.offline.*` | `state.info.*` / `state.neutral.*`，分别配等待/离线文字。 |
| `color.sync.conflict.*` / `color.sync.paused.*` | `state.warning.*` / `state.neutral.*`。 |
| `color.privacy.sensitive.*` | `state.neutral.*` + 锁图标；不能暗示错误。 |
| `color.selection.current` | `action.primary` + 2 px 轮廓 + selected/current 语义。 |

别名即使暂时复用同一色值也必须保留独立名称，以便未来调整而不改变业务代码。`attention.overdue` 与 `state.danger` 语义不同，必须由文字、图标和组件结构区分。

### DS-022：交互颜色规则

- 主动作：使用 `action.primary + action.onPrimary`，一个页面最多一个视觉主动作；
- 次动作：透明或 `surface.default` 背景，使用 `text.primary + border.strong`；
- 三级动作：文字/图标按钮，使用 `text.link` 或 `text.primary`，仍保留命中区域；
- 破坏性动作：默认使用 danger 前景的次按钮；只有最终不可逆确认可用 danger 实色按钮；
- 选中：使用 2 px `action.primary` 轮廓、选中图标和文字状态，不能只改变底色；
- disabled：视觉降低强调但不隐藏；关键原因靠近控件展示；
- pressed/hover/focus 可以叠加，focus ring 不能被 pressed 背景覆盖。

### DS-023：记录类型识别

五种记录使用固定图标与文字名称，不分配永久“类型色”。同一类别颜色可以跨记录类型使用，避免用户误把绿色同时理解为“重复事项”“成功”和某个分类。允许在营销插图中使用多色，但产品列表仍以类型图标 + 类型文字为准。

### DS-024：空间与成员识别

当前空间必须持续显示名称；家庭空间可使用 house/group 图标，个人空间使用 person/book 图标。空间头像或装饰色只作辅助，不能把颜色当授权或空间 ID。失权、只读、待删除和成员角色使用明确文案与状态徽标。

### DS-025：分类与标签颜色注册表

领域字段 `Category.colorToken` 与 `Tag.colorToken` 只保存下列稳定注册值；主题负责解析实际颜色。

| 持久化值 | Light 前景 / 背景 | Dark 前景 / 背景 |
| --- | --- | --- |
| `teal` | `#175E50` / `#DDF1EA` | `#8DDEC6` / `#17372E` |
| `blue` | `#245C92` / `#E4EFFA` | `#A8D0FF` / `#18334D` |
| `violet` | `#614A91` / `#EEE8F8` | `#D1BDF5` / `#332B49` |
| `rose` | `#8C3657` / `#F9E7EE` | `#F2B7CC` / `#49283A` |
| `amber` | `#7A4700` / `#FFF0D6` | `#FFD08A` / `#46331C` |
| `olive` | `#52631F` / `#EDF1D9` | `#C8D68D` / `#303821` |
| `slate` | `#4A5953` / `#E9EEEB` | `#C8D1CC` / `#29322E` |

规则：

- `null` 或旧客户端未知值以 `slate` 显示，但必须保留原始值，不能在只读时回写；
- 新建选择器默认突出 `teal`，只有用户保存后才写入；
- 每个 chip 同时显示分类/标签文字；不能用一排无标签色点作为唯一选择器；
- 注册值一经写入同步数据或备份，不得改义或复用；弃用时保留解析别名并提供显式迁移；
- 后续允许扩展注册表，但旧客户端必须以 `slate` 安全降级，不因未知颜色拒绝整个实体。

## 4. 排版

### DS-030：字体族

界面使用系统字体栈，中文不随 App 打包自定义正文字体：iOS 使用系统 San Francisco/苹方回退，Android 使用系统 Roboto/Noto Sans CJK 回退，Web 使用 `system-ui` 与平台中文字体回退。这样保留动态字体、字形覆盖、粗体与系统可读性设置。

品牌 Logo 可以使用独立字形资产，但不得替代导航标题、按钮或正文。用户输入、数字、单位和混合语言不能强制使用缺少字符的品牌字体。

### DS-031：文本样式

| 令牌 | 基准字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `type.display` | 32 / 40 | 600 | 极少量首屏欢迎或关键空状态。 |
| `type.title.1` | 28 / 36 | 600 | 大页面标题。 |
| `type.title.2` | 22 / 30 | 600 | 页面/弹层主标题。 |
| `type.title.3` | 18 / 26 | 600 | 分区与卡片标题。 |
| `type.body.large` | 17 / 26 | 400 | 重点正文。 |
| `type.body` | 16 / 24 | 400 | 默认正文与输入。 |
| `type.body.small` | 14 / 21 | 400 | 次要说明。 |
| `type.label.large` | 16 / 22 | 600 | 主按钮、重要控件。 |
| `type.label` | 14 / 20 | 600 | chip、状态与次控件。 |
| `type.caption` | 12 / 18 | 400 | 非关键元数据；不得承载唯一错误或风险。 |

字号是未缩放基准，不是固定像素高度。实现映射到平台可缩放文本样式；容器随内容增长。中文正文默认不加字距，英文全大写不作为常规标签。长 ID 可用等宽字体仅在“技术详情”中展示。

### DS-032：数字与数量

库存数量、进度和日期使用支持 tabular numbers 的系统字体特性时，不得影响中文单位字形。数值、正负变化、单位、确认/预估和状态是独立文本节点；不得用字号差让单位不可读。大数值至少仍提供一行完整的可访问值。

### DS-033：截断与行数

- 导航标题：默认一行，主体区域提供完整安全名称；
- 列表标题：手机最多两行，超出后同一行/详情入口可获得全文；
- 说明摘要：默认两至三行，可省略但不能让状态、单位和风险一起消失；
- 按钮、错误、危险影响、状态徽标和日期数量不得只显示省略号；
- 动态字体使横向内容放不下时改纵向，不缩小到另一个 token。

## 5. 间距、尺寸、形状与层级

### DS-040：间距比例

| 令牌 | 值 | 常见用途 |
| --- | ---: | --- |
| `space.0` | 0 | 重置。 |
| `space.0_5` | 2 | 图形微调，不用于命中区。 |
| `space.1` | 4 | 紧密图标/文字。 |
| `space.2` | 8 | 组件内部小间距。 |
| `space.3` | 12 | 控件内部、列表次级间距。 |
| `space.4` | 16 | 手机页边距、卡片内边距。 |
| `space.5` | 20 | 表单组。 |
| `space.6` | 24 | 分区间距。 |
| `space.8` | 32 | 大分区。 |
| `space.10` | 40 | 首屏节奏。 |
| `space.12` | 48 | 页面级分隔。 |
| `space.16` | 64 | 宽屏大留白。 |

默认使用 4/8 基线；2 只用于光学校正。页面不能为了对齐而给每个实例新增任意值。

### DS-041：命中尺寸和控件高度

- iOS 最小热区 44×44 pt，Android 48×48 dp；Web 常规控件优先 44×44 CSS px；
- 主/次按钮视觉最小高度：iOS 44 pt、Android 48 dp；紧凑桌面工具栏也不能低于适用可访问性门槛；
- 文本输入单行视觉最小高度 48，实际高度随帮助、错误和字体增长；
- 相邻小图标的热区不重叠，行内按钮与整行点击必须明确命中优先级；
- 固定底部动作区包含安全区 inset，不能遮住最后一个字段或焦点环。

### DS-042：圆角

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `radius.xs` | 4 | 焦点内层、微型标记。 |
| `radius.sm` | 8 | 输入、chip、小卡片。 |
| `radius.md` | 12 | 常规卡片、按钮。 |
| `radius.lg` | 16 | 大卡片、bottom sheet 顶部。 |
| `radius.xl` | 24 | 空状态插图容器。 |
| `radius.full` | 999 | 圆形按钮、短状态胶囊；不用于长段文字。 |

嵌套表面遵循“外圆角 ≥ 内圆角 + 间距”；不能用不同圆角暗示不存在的业务层级。

### DS-043：边界与阴影

- `border.width.default = 1`，选中与焦点内边界为 2；
- `elevation.0` 无阴影；`elevation.1` 用于轻浮卡片；`elevation.2` 用于菜单/sheet；`elevation.3` 只用于 modal；
- Light 参考阴影分别为 `0 1 2 rgba(18,34,28,0.08)`、`0 4 12 rgba(18,34,28,0.12)`、`0 12 32 rgba(18,34,28,0.18)`；平台适配器转换为原生 elevation/shadow；
- Dark 主题优先以表面亮度和 `border.default` 分层，阴影只是补充；
- 重要边界不能只靠阴影，增强对比度时需提升为 `border.strong`。

## 6. 图标、图片与数据可视化

### DS-050：图标体系

使用一套轮廓一致、平台可识别的图标集；同一语义不得在不同页面换图。常规图标视觉尺寸 20 或 24，导航/关键类型图标 24，紧凑辅助图标 16；命中区仍按 DS-041。

| 语义 | 固定方向 |
| --- | --- |
| 重复事项 | 循环箭头 + “重复事项”文字。 |
| 清单 | 方框清单 + “清单”文字。 |
| 备忘 | 文档/便笺 + “备忘”文字。 |
| 重要日期 | 日历标记 + “重要日期”文字。 |
| 家庭物品 | 收纳盒/物品 + “家庭物品”文字。 |
| 敏感 | 锁；未解锁不显示对象特有图形。 |
| 待同步/冲突 | 云或双箭头并带文字状态。 |

装饰图标从可访问性树移除；图标按钮提供独立名称。不得用相似的实心/空心差异作为唯一状态线索。

### DS-051：用户图片和缩略图

- 默认缩略图比例 1:1，列表尺寸 48；详情图片按内容比例但限制最大高度并可进入查看器；
- 加载、缺失、损坏、敏感遮罩分别使用不同文字状态，不显示系统文件路径；
- 缩略图裁切不改变原文件，详情提供完整查看；
- skeleton 不复刻敏感内容长度或附件数量；
- OCR/识别框只在用户主动校对时显示，不把识别置信度仅画成颜色热图。

### DS-052：图表边界

P0 不需要完成率、连续天数或库存趋势图。后续确需图表时必须同时提供数据摘要、可访问数据表/列表、单位、时间范围和非颜色系列标识；图表不得把派生缓存表现为不可质疑的权威事实。

## 7. 响应式布局

### DS-060：宽度档位

档位按可用内容宽度判断，不按设备名称判断：

| 档位 | 可用宽度 | 默认结构 |
| --- | ---: | --- |
| `compact` | `< 600` | 单栏；页边距 16；卡片满宽。 |
| `medium` | `600–839` | 单栏或列表/详情过渡；页边距 24；表单内容最大 640。 |
| `expanded` | `>= 840` | 允许列表/详情双栏；页边距 32；主内容最大 1200。 |

P0 只承诺 compact 手机专门优化，medium/expanded 至少保持功能完整、无裁切和正确返回；P2 Web 才把键盘、双栏和窄视口作为完整交付矩阵。断点不能改变业务命令、权限或信息是否存在。

### DS-061：页面骨架

- 普通手机页：安全区 → 导航标题 → 可选状态摘要 → 滚动主体 → 可选固定主动作；
- 表单正文最大 640，阅读型长文最大 720；列表/详情总宽最大 1200；
- compact 页面使用 4 列概念网格，medium 8 列、expanded 12 列，栏间距分别 16/20/24；页面可用更简单的堆叠布局，不要求逐项对齐隐形网格；
- 双栏中列表建议 320–400，详情占剩余空间；逻辑阅读顺序仍为列表后详情；
- 底部导航只用于四个顶层目的地，不把次级功能挤成第五个业务标签。

### DS-062：重排顺序

空间不足时依次：允许文字换行 → 元数据移到下一行 → 次动作移入有标签的更多菜单 → 卡片改纵向 → 页面改为单栏。不得先隐藏错误、状态、单位、空间名称、危险影响或主动作。RTL 本地化时镜像导航与方向图标，时间轴、数字符号和用户内容按 locale/bidi 规则处理。

### DS-063：虚拟列表与稳定布局

长列表使用稳定实体 ID、估算高度和增量测量；字体变化、状态徽标和图片加载不能把当前焦点移出。加载更多使用列表内状态而不是全屏刷新；空、加载、离线和筛选无结果是四种不同布局状态。

## 8. 共享组件契约

### DS-069：页面状态词与视觉槽

页面必须原样覆盖 SCR 1.3 的状态。设计/代码可以用内部状态机组合，但不得把所有失败压成一个 `error`：

| 页面状态 | 呈现契约 |
| --- | --- |
| `initializing` | 首次读取；300 ms 内不闪占位，之后显示结构骨架。普通后台刷新不回到此状态。 |
| `empty` | 已成功读取且集合为空；说明原因与真实下一步，不能仍显示 spinner。 |
| `partial` | 主体可用，局部以 info/warning/danger 标出缺失或损坏，不盖全页。 |
| `offline` | 作为 banner/局部状态；可用本地动作保持正常层级。 |
| `permission_missing` | 显示受影响能力、修复入口和替代路径，不伪装成网络错误。 |
| `retryable_error` | 保留内容/输入并提供具体重试，通常使用局部 danger。 |
| `blocked_error` | 全页保护状态、诊断 ID 与安全恢复路径；不得继续写入。 |
| `saving` | 用户命令进行中；主动作 busy、防重复，离开需按流程确认。 |
| `locked` | 安全占位；真实内容组件尚未实例化。 |
| `stale` | 当前投影过旧但尚未证明发生并发冲突；提供刷新/重新读取。 |
| `conflict` | 已确认存在两份不可自动合并版本；使用 warning 与选择入口。 |

内部通用 `loading` 必须细分：首次加载映射 `initializing`，局部后台读取映射组件自身 busy，提交映射 `saving`。`stale/conflict` 共用页面槽但保持两个不同事实；通用 `error` 不能穿过页面组件 API，必须先映射为 permission、retryable 或 blocked 等受控类别。

### DS-070：组件公共状态

每个可交互组件必须定义适用的 `default | hover | pressed | focused | checked | selected | expanded | disabled | busy | invalid | readOnly | current` 状态。状态可以组合，例如 `focused + invalid`；实现不得用互斥样式让焦点覆盖错误或让 busy 恢复可重复点击。组件的 `busy` 是可访问状态，视觉可按场景显示 spinner/progress；页面是否处于 `saving` 由 DS-069 决定。

共享组件目录中的每项还必须完成 A11Y 第 10 节契约，并记录：令牌依赖、内容长度、主题截图、键盘/触控行为、埋点边界和破坏性动作等级。

### DS-071：按钮

| 变体 | 用途 | 限制 |
| --- | --- | --- |
| `primary` | 当前任务的提交/继续。 | 同一任务区一个；不得用于“取消”。 |
| `secondary` | 可并列的安全替代。 | 有清晰边界。 |
| `tertiary` | 低强调动作、行内入口。 | 仍满足命中区。 |
| `destructive` | 永久删除、清除、放宽保护。 | 可恢复删除通常只用 danger 文本/次按钮。 |
| `icon` | 关闭、更多、排序等熟悉动作。 | 必须有可访问名称和 tooltip（Web）。 |

loading 时保留按钮宽度、显示“正在…”文本或进度并屏蔽重复提交；失败后恢复原动作和输入。按钮文案使用 CONTENT-011，不用只有“确定”的通用标签。

### DS-072：文本输入与选择器

- 持续可见 label；placeholder 只给格式示例；帮助、计数、单位和错误各有稳定槽位；
- 默认边界用 `border.strong`，聚焦叠加 `focus.ring`，错误叠加 danger 图标和文字；
- readOnly 与 disabled 分开：readOnly 内容仍可选择/复制，disabled 不可操作并说明原因；
- 多行正文随输入增长到页面上限后内部滚动，不能默认压成单行；
- 日期、时间、重复、数量和单位使用领域选择器，但提交前始终给出文本摘要；
- 选择器取消不修改已保存值；临时选择和权威值视觉上不可混为一体。

### DS-073：选择控件

- checkbox 表达多个独立选项或清单完成；radio 表达一个集合中的单选；switch 只表达立即生效且可逆的设置；
- “永久删除”“加入家庭”“发送敏感上下文”等提交命令不得用 switch；
- segmented control 最多 2–4 个短且同层选项，动态字体放不下时改列表；
- chip 分为 `filter`（可操作）与 `label`（静态），两者不能只靠填充色区分；
- 清单 checkbox 的选中视觉不删除标题可读性；划线只作补充。

### DS-074：列表行、卡片与分区

- 优先使用列表行；只有需要组合状态、摘要和快捷动作时使用卡片；
- 行/卡片顺序固定为：类型/缩略 → 安全标题 → 原因/摘要 → 时间与状态 → 主动作/更多；
- 整行可点击时，行内快捷动作拥有独立命中区；不能在卡片内嵌套另一个可点击卡片；
- 分区标题描述内容而非装饰，列表之间使用间距或边界，不为每行增加高阴影；
- swipe 和长按都必须有可见菜单替代；删除后焦点与撤销遵循页面和可访问性规范。

### DS-075：徽标、标签与计数

状态 badge 使用 DS-021 的前景/背景、图标和完整文字；不能只写首字母或色点。数字 badge 超过 99 显示“99+”仅作视觉摘要，可访问名称仍读真实受控数量。分类/标签 chip 使用 DS-025；空间、同步和敏感使用各自领域组件，不能复用分类色造成误解。

### DS-076：导航

- 底部导航显示图标和文字，选中同时使用形状/字重/语义，不只换色；
- 顶栏主标题稳定，返回行为显示来源语义；关闭 modal 与返回页面不是同一个图标动作；
- tab 切换保存各自安全滚动位置，但空间切换、失权或锁定必须清受保护栈；
- 面包屑只用于 P2 Web 多层整理，不在手机重复顶部返回；
- 深链接失败使用页面状态与合法返回动作，不静默跳到不相关首页。

### DS-077：反馈组件

| 组件 | 使用 | 不使用 |
| --- | --- | --- |
| inline message | 字段/局部状态、可恢复错误。 | 跨页面唯一通知。 |
| banner | 页面级离线、只读、待删除、同步暂停。 | 每个普通保存成功。 |
| toast | 短暂、非关键成功和可选撤销。 | 永久删除确认、长风险说明。 |
| full-page state | 首次空、权限失效、完整性保护、不可恢复加载失败。 | 局部网络错误。 |
| notification dot | 有待查看内容的辅助提示。 | 真实数量、紧急保证。 |

反馈同时使用状态标题、正文和动作；同一错误不能同时弹 toast、banner 和 modal。公告方式由 A11Y-012 决定。

### DS-078：对话框、bottom sheet 与菜单

- 简短二选一确认使用 alert/dialog；需要预览、输入、三项以上选择或长风险时使用独立页面/sheet；
- bottom sheet 最小高度由内容决定，最大高度后内部滚动；键盘出现时主动作可见；
- 危险确认的安全动作在阅读顺序中先出现，视觉位置遵循平台约定；
- menu 项使用动词 + 对象，破坏性项与普通项分组但不靠红色单独表达；
- 打开后限制焦点，关闭后回触发点；背景内容从交互和可访问性树禁用。

### DS-079：加载、进度与空状态

- 预计少于 300 ms 不闪现 spinner；超过 300 ms 显示局部状态；超过 1 秒的用户命令显示可理解阶段；
- skeleton 只用于结构已知的读取，不用于保存、恢复或加密验证；动画遵循 Reduce Motion；
- determinate progress 只在总量可信时使用；备份、恢复、导入等显示“已处理 N / 总数”与当前阶段；
- 空状态遵循 CONTENT-040，插图可选且不占据主动作之前的主要阅读顺序；
- 后台仍可继续的任务提供离开后的可发现状态，不能用永不结束的 modal 锁住 App。

### DS-080：敏感与应用锁组件

组件至少提供 `locked | masked | revealed | reauthRequired` 四种视图状态：

- `locked`：全页安全入口和认证动作，不实例化真实内容组件；
- `masked`：只使用“敏感记录”这一通用标题、锁图标与“打开敏感记录”；不得显示五种真实记录类型、事件种类、家庭名，也不显示长度相同的伪文本；
- `revealed`：只在授权窗口内渲染，离开/后台按安全规则清理；
- `reauthRequired`：说明将执行的高风险动作，认证取消后不改变数据。

屏幕截图测试必须证明视觉树与可访问性树都不包含被遮罩值。

### DS-081：领域专用组件

以下组件必须共享实现，页面不得自行拼装状态：

| 组件 | 必须展示 |
| --- | --- |
| `RecordTypeMark` | 固定类型图标 + 类型文字。 |
| `RecordLifecycleBadge` | 归档/回收站及可恢复含义；active 通常不显示。 |
| `AttentionReason` | 为什么出现在“今天”、对应业务时间和合法动作。 |
| `QuantityValue` | 确认数量、单位；有待同步时分开展示预估。 |
| `StockChangeSummary` | before、delta、after、动作类型及 confirmed/pending/rejected。 |
| `ReminderStatus` | 计划/实例状态与精确或近似能力，不声称送达。 |
| `SyncStatus` | 已保存在本机、等待同步、已同步、冲突/暂停及作用空间。 |
| `SpaceContext` | 空间名称、个人/家庭、角色/只读状态。 |
| `SensitivityMark` | 锁图标 + “敏感”；受保护时不含对象标题。 |
| `AiProvenance` | inferred/default/用户修改/已确认的文字来源说明。 |

## 9. 领域状态呈现映射

### DS-090：映射原则

状态名称和迁移完全由领域/专项规范定义。新增领域状态时，必须先在权威规范定义含义，再在此表增加呈现；设计稿不得发明后端状态。状态角色只是视觉优先级，不能驱动业务分支。

| 领域状态 | 状态角色 | 必须有的非颜色线索 |
| --- | --- | --- |
| Record `active` | 通常无 badge | 正常页面位置。 |
| Record `archived` | neutral | “已归档”+ archive 图标。 |
| Record `trashed` | neutral；临近清理可 warning | “回收站”+ 绝对清理日期。 |
| Occurrence `pending` | info/neutral | “待处理”+ 日期。 |
| Occurrence `completed` | success | “已完成”+ check。 |
| Occurrence `skipped` | neutral | “已跳过”+ skip。 |
| Occurrence `overdue` | `attention.overdue` | “已逾期”+ 原业务日期，不整卡标红。 |
| Checklist 进行中/已完成/已逾期 | info / success / `attention.overdue` | 状态文字 + `已完成 N / 总数`。 |
| 库存充足 | 通常无 badge | 确认数量 + 单位。 |
| LowStockEpisode 活跃 | warning | “需要补货”+ 数量/阈值；当前收件人确认另显。 |
| StockChangeIntent pending | info | “待同步预估”，与确认数量分行。 |
| StockChangeIntent rejected | danger | “未过账”+ 原因 + 修复动作。 |
| ReminderInstance planned/scheduled | info | “等待安排/已安排”+ 时间 + 精确/近似。 |
| ReminderInstance acknowledged/snoozed | success/info | “已知道/已稍后”+ 当前收件人语义。 |
| ReminderInstance paused/cancelled/expired | neutral | 完整状态与是否会恢复/补发。 |
| NotificationDelivery failed | danger | “安排失败”或受控失败文案；不得写“未送达”。 |
| Sync 等待/进行中/成功 | info / info / success | 文字 + 作用空间 + 数量（适用时）。 |
| Sync conflict/rejected | warning/danger | “需要你选择/未同步”+ 修复入口。 |
| Attachment processing/available/missing/corrupt | info / 无 / danger / danger | 文件状态文字 + 合法下一步。 |
| AI inferred/default/用户确认 | info / neutral / success | 来源文字，不显示虚假精确置信度。 |
| Family subscription active + mode=off | neutral | “已关闭本人提醒”，不写 cancelled。 |
| Family subscription paused | warning/neutral | “同步暂停/家庭待删除期间暂停”+ 恢复条件。 |
| Family subscription cancelled | neutral | “已取消”+ 终态原因。 |

### DS-091：优先级合并

一个对象同时有多个状态时不堆叠所有徽标：

1. 先展示阻止安全访问或写入的状态：locked、失权、完整性保护、只读；
2. 再展示需要用户修复的状态：冲突、库存意图拒绝、提醒安排失败；
3. 再展示业务关注原因：逾期、低库存、今日到期；
4. 最后展示普通生命周期和来源：归档、同步成功、AI provenance。

次级状态保留在详情或展开区。合并只改变展示密度，不吞掉业务状态；读屏摘要说明“还有 N 个状态”并可展开。

## 10. 动效与触觉

### DS-100：时长与曲线

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `motion.duration.instant` | 0 ms | Reduce Motion、立即状态。 |
| `motion.duration.fast` | 100 ms | pressed、hover、微反馈。 |
| `motion.duration.standard` | 180 ms | 展开、淡入、状态切换。 |
| `motion.duration.emphasized` | 260 ms | sheet/modal 进入；不用于重复循环。 |
| `motion.easing.standard` | `cubic-bezier(0.2,0,0,1)` | 普通进入/改变。 |
| `motion.easing.exit` | `cubic-bezier(0.4,0,1,1)` | 离开。 |

大范围页面位移、弹簧回弹、视差和自动缩放不属于品牌默认。Reduce Motion 下保留必要因果的即时替换或短淡入，不改变命令完成时机。

### DS-101：触觉与声音

触觉只用于用户发起的明确结果：轻触选择、完成、警告/失败；高频清单批量操作合并反馈。声音默认由系统通知和系统设置管理，App 内不自定义成功音。任何触觉/声音都必须同时有文字或语义状态。

## 11. 本地化、主题与内容韧性

### DS-110：本地化扩展

- 布局至少用中文基线文本 1.5 倍长度验证，按钮不依赖固定宽度；
- 日期、时间、数量、单位和复数由 locale 格式化，不能通过字符串拼接对齐；
- 用户内容可以是任意 Unicode 与双向文字，容器不能把控制字符解释为布局命令；
- 图标避免依赖中文谐音或文化暗示；公开模板插图需单独本地化审核；
- 品牌“生活有谱”不自动翻译，海外品牌在 OQ-009 关闭后另行定版。

### DS-111：系统外观改变

系统外观改变不重建业务草稿、不改变图片/附件内容、不触发领域 mutation。正在展示敏感内容时切后台或系统截屏仍先执行隐私遮罩，再绘制新主题。P0 没有需要备份的主题偏好；未来若增加手动选择，它只能作为非敏感、按安装/账号约定的个人偏好，不能成为改变其他成员界面的家庭设置。

## 12. 工程使用约束

### DS-120：唯一组件入口

产品页面必须从共享组件与令牌包导入，禁止：

- 页面内硬编码颜色、字号、z-index、阴影和常用间距；
- 复制一个组件后只改局部状态而不回馈组件目录；
- 用业务状态字符串直接拼 CSS class；
- 用最终中文文本作为唯一 testID、路由 ID 或图标名；
- 让远程配置注入任意颜色、HTML/CSS 或跳过危险确认。

确有一次性视觉需要时，先登记用途、适用主题、可访问性结果和移除条件；连续出现两次即评估升为令牌/组件。

### DS-121：层级与 portal

统一层级顺序为：页面内容 → 粘性导航/动作 → 菜单与 sheet → modal → 系统级锁定/完整性保护。Toast 不得盖住 modal 主动作、键盘输入或焦点。实现使用受控 portal/overlay manager，不允许页面随意设置超大 z-index。

### DS-122：设计交付最小信息

每个 `SCR-*` 的设计交付必须包含：

- compact 默认、最大动态字体、dark、loading、empty、error、offline、locked/sensitive 的适用稿；
- 字段与领域对象/临时状态的映射；
- 主次动作、危险等级、返回与焦点结果；
- 使用的共享组件、令牌和例外；
- 关键内容长度、键盘、安全区和权限系统页场景；
- 对应需求/规则编号和可访问性验收项。

## 13. 验证与发布门槛

### DS-130：自动化

持续集成至少验证：

- 令牌注册表 Schema、重复名称、主题完整性、废弃别名和未知引用；
- Light/Dark 的正文、状态、边界、焦点和按钮对比度；
- 产品源代码中禁止的原始颜色/任意字号规则（允许范围只在令牌包和测试夹具）；
- 共享组件的 default/pressed/focused/disabled/loading/error 视觉回归；
- compact、最大字体、dark 和敏感遮罩的关键页面截图；
- 分类 `colorToken` 的全部已知值和未知值安全回退；
- Reduce Motion 下不存在持续位移、快速闪烁或被隐藏的状态结果。

### DS-131：人工评审矩阵

每个发布候选至少抽查五类创建/详情、“今天”、家中、提醒、备份恢复和危险确认；对应阶段再抽查账号同步、导入、家庭和 Web。每项覆盖：

- Light、Dark、系统增强对比度；
- 最低支持与主流尺寸、横屏/分屏可用性；
- 最大动态字体和最长受控文案；
- 离线、错误、权限拒绝、只读、敏感和失权；
- 触控、读屏/键盘焦点以及手势替代；
- 实际系统通知、分享、认证、相册/文件选择等平台边界。

### DS-132：缺陷门槛

以下问题阻止对应阶段发布：敏感数据视觉或结构泄露、主动作在支持尺寸/字体下不可达、状态只靠颜色、危险动作层级误导、关键文字/控件对比不达标、主题切换丢失草稿、组件状态与领域事实相反。普通像素偏差只有在不影响理解、可访问性或品牌一致性时才可按一般缺陷处理。

### DS-133：变更影响检查

修改语义颜色、组件状态、断点或持久化颜色注册值时，至少检查：设计稿与组件库、Light/Dark/高对比度、截图基线、内容长度、可访问性树、备份/同步向前兼容、页面状态映射和商店素材。涉及 `colorToken` 注册值的破坏性改变必须先有数据迁移决策，不能仅改设计文件。
