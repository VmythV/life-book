# 生活有谱产品功能说明

> 项目代号：`life-book` · 版本：v0.1 · 更新日期：2026-07-23 · 状态：功能基线

## 1. 产品概述

生活有谱是一款面向个人与家庭生活的记录和提醒工具。它将重复日常、可复用清单、备忘、重要日期及家庭物品放在同一个生活簿中，让容易遗忘、散落在不同工具里的生活信息变得清楚、可靠、有着落。

产品的核心价值不是督促用户提高效率，而是减少记忆负担：该做的事情会出现，该准备的东西有清单，重要的日子不会错过，家里有什么也心中有数。

### 1.1 品牌主张

> **每件生活小事，都有着落。**

### 1.2 一句话介绍

一个帮你安排重复日常、复用各类清单、记住重要日子，并掌握家中物品存量的生活记录工具。

### 1.3 P0 核心用户

经常需要记住生活琐事、准备各种清单和管理家中物品，但不喜欢复杂效率工具的个人用户。

这类用户希望少记在脑子里，而不是追求更高的任务完成率。产品应当降低记录和查找成本，不要求用户先理解复杂的效率方法。

### 1.4 第一核心场景

> 用户想到一件生活小事，点击加号，用一句话记录，确认后在正确时间再次看到它。

核心体验链路：

```text
快速记下
→ 自动整理
→ 用户确认
→ 准时出现
→ 长期可查
```

智能创建体现产品的第一印象，清单模板和家庭库存为用户提供长期使用价值。

## 2. 产品目标

1. 用一个入口管理常见的个人和家庭生活记录。
2. 让用户既可以手动创建，也可以用自然语言快速创建。
3. 让提醒可靠、清楚，同时避免制造不必要的焦虑。
4. 保证记录易于搜索、修改、归档和导出。
5. 第一阶段优先满足个人使用，并为以后家庭共享保留数据结构。

## 3. 暂不作为产品目标

- 不做企业项目管理或团队绩效工具。
- 不做公开社交社区。
- 不在第一版建设公共模板市场。
- 不要求所有功能依赖大模型才能使用。
- 不允许大模型在未经确认的情况下直接修改用户数据。

## 4. 核心产品决策

| 决策 | 说明 |
| --- | --- |
| 统一生活簿 | 五种记录共享分类、标签、搜索和归档能力，但使用不同的创建表单。 |
| 个人优先 | 第一版以个人空间为主，后续增加家庭成员和共享权限。 |
| 智能创建是输入方式 | 大模型不是独立聊天模块，而是加号按钮中的自然语言创建方式。 |
| 先生成草稿 | 模型只负责理解和整理，程序校验后必须由用户确认才能保存。 |
| 模板与实例分离 | 清单模板不会因为某一次使用被永久勾选。 |
| 库存保留流水 | 家庭物品的购入、使用和调整都形成记录，不能只保存最终数量。 |

### 4.1 首次使用流程

首次打开直接进入可创建记录的页面，不强制注册、不展示教程轮播，也不自动创建示例数据。

首屏包括：

- 品牌名称和主张
- “先记下一件你不想忘的小事”的行动提示
- 一句话创建输入框
- 贴近日常的输入示例
- 重复事项、清单、备忘、重要日期和家庭物品手动入口

首次体验目标是让用户在一分钟内开始创建第一条真实记录。

### 4.2 权限按需申请

- 创建第一条带时间记录时申请通知权限。
- 主动开启应用锁时申请生物识别或设备验证权限。
- 使用语音输入时申请麦克风权限。
- 添加图片时申请相册或相机权限。
- 开启云同步时再引导注册和登录。

申请系统权限前先使用一段简短文案说明用途。用户拒绝后保留手动替代路径和重新开启权限的入口，不能让创建流程卡死。

### 4.3 首次使用智能创建

首次点击“帮我整理”时，展示一次简短隐私说明：

> 本次输入会发送给智能服务进行整理。默认不会发送生活簿中的其他记录，确认前不会保存任何内容。

确认后记住选择。敏感记录和“禁止用于智能功能”的设置不受该选择影响。

### 4.4 创建成功反馈

成功反馈必须展示具体结果，例如：

```text
已经替你记好了
每周日 21:00 提醒“整理下周计划”
```

同时提供查看记录、再记一件和返回今天三个后续操作。

### 4.5 空页面与备份提示

- 今天：“暂时没有需要处理的事。”
- 生活簿：“先记下一件不想忘的小事。”
- 家中：“记录第一件常用物品，补货时就不用靠猜。”
- 清单：“从旅行、搬家或采购模板开始。”

用户已经创建至少一条真实记录，并达到累计 5 条记录或使用 7 天中的任一条件后，再首次提示创建加密备份。关闭提示后不频繁重复打扰。

## 5. 信息架构

第一版采用四个底部导航入口，并提供一个全局加号按钮。

### 5.1 今天

首页首先回答三个问题：

- 今天有什么要做？
- 最近有什么不能忘？
- 家里有什么需要补充？

聚合当前需要关注的内容：

- 已逾期但尚未处理的事项
- 今天需要完成的重复事项
- 今天到期的备忘和清单
- 今天发生的重要日期
- 即将到来的重要日期
- 低库存提醒

支持直接完成、跳过、稍后提醒或打开详情。

首页不优先展示完成率、连续天数和复杂统计，避免把生活记录变成绩效面板。

### 5.2 生活簿

浏览和管理全部记录：

- 按记录类型查看
- 按分类、标签和状态筛选
- 全文搜索
- 查看最近创建和最近修改
- 查看归档内容

### 5.3 家中

集中管理家庭物品：

- 物品列表
- 当前库存
- 低库存项目
- 最近的购入和消耗记录
- 存放位置
- 补货清单

### 5.4 我的

- 通知和默认提醒设置
- 分类和标签管理
- 数据备份、导入及导出
- 大模型服务设置
- 隐私与安全设置
- 家庭空间与成员管理（后续版本）

### 5.5 全局加号

点击加号默认打开“一句话创建”，同时保留五种记录的手动创建入口。

## 6. 通用记录能力

五种记录都可使用以下公共字段和操作。

### 6.1 公共字段

- 标题
- 详细说明
- 分类
- 标签
- 图片或附件
- 创建时间
- 最后修改时间
- 归档状态
- 与其他记录的关联关系

### 6.2 公共操作

- 创建
- 查看
- 编辑
- 复制
- 归档
- 删除
- 搜索
- 分享或导出（分阶段提供）

删除的记录先进入回收站并默认保留 30 天；永久删除和清空回收站需要二次确认。

## 7. 重复事项

用于记录按固定或自定义周期重复发生的事情，例如每天吃药、每周换床单、每月交水电费。

### 7.1 基础字段

- 标题
- 说明
- 开始日期
- 结束日期，可为空
- 执行时间，可为空
- 重复规则
- 提醒时间
- 分类和标签

### 7.2 重复规则

- 每天
- 每周
- 每月
- 每年
- 每隔 N 天、N 周或 N 月
- 每周指定星期几
- 每月指定日期
- 自定义结束日期或重复次数

### 7.3 单次执行状态

- 待完成
- 已完成
- 已跳过
- 已逾期

### 7.4 关键规则

- 某一次未完成，不影响下一周期正常生成。
- 用户可以只修改本次，也可以修改本次及以后。
- 跳过与完成必须区分，便于保留真实记录。
- 修改重复规则时不得破坏已经发生的历史记录。

### 7.5 后续能力

- 完成率和趋势
- 连续完成记录
- 与家庭成员分工

统计用于帮助回顾，不使用带压力的排名或惩罚表达。

## 8. 清单

用于旅行、搬家、待产、露营、采购等需要逐项准备的场景。

### 8.1 清单结构

- 清单名称
- 说明
- 分组
- 清单项目
- 完成状态
- 截止日期
- 提醒时间
- 总体完成进度

### 8.2 清单项目

每个项目支持：

- 标题
- 说明
- 数量
- 是否完成
- 所属分组
- 排序

### 8.3 模板与实例

系统必须区分：

- **清单模板**：例如“通用旅行准备清单”。
- **清单实例**：例如“2026 年 10 月北京旅行”。

从模板创建实例后，实例中的勾选和修改不能影响原模板。用户可以把一个实际清单另存为新模板。

### 8.4 主要操作

- 新建空白清单
- 从模板创建
- 添加、编辑、删除和排序项目
- 添加和调整分组
- 批量完成或取消完成
- 复制清单
- 保存为模板
- 归档已结束的清单

## 9. 备忘

用于保存暂时不需要执行，但未来需要查找的重要信息，例如设备型号、注意事项或联系方式。

### 9.1 基础字段

- 标题
- 正文
- 图片或附件
- 分类和标签
- 可选提醒时间
- 关联的物品、日期或其他记录

### 9.2 关键规则

- 备忘默认没有完成状态。
- 添加提醒不会把备忘自动转换为重复事项。
- 提醒结束后，备忘内容仍然保留。

### 9.3 主要操作

- 快速记录
- 置顶
- 全文搜索
- 添加附件
- 关联其他记录
- 设置一次或多次提醒
- 归档

## 10. 重要日期

用于生日、纪念日、证件到期、保险续费和保修到期等与日期相关的记录。

### 10.1 基础字段

- 标题
- 日期
- 日期类型
- 是否重复
- 起始年份，可为空
- 提醒计划
- 关联人物或物品
- 说明

### 10.2 日期类型

- 仅一次
- 每年重复
- 公历
- 农历（后续版本）

### 10.3 提醒计划

支持为同一日期设置多次提醒，例如：

- 提前 30 天
- 提前 7 天
- 提前 1 天
- 当天指定时间

### 10.4 展示规则

不同日期类型使用符合场景的文案：

- “结婚纪念日还有 7 天。”
- “护照将在 90 天后到期。”
- “今天是妈妈的生日。”

如果记录了起始年份，可以显示“第 N 周年”或年龄，但应允许用户关闭。

## 11. 家庭物品

用于记录日用品、药品、耗材、家电和贵重物品的数量及相关信息。

### 11.1 基础字段

- 名称
- 图片
- 当前数量
- 单位
- 最低库存
- 存放位置
- 分类和标签
- 说明

### 11.2 库存操作

- 买入：数量增加并记录来源
- 使用：数量减少
- 调整：将数量修正为实际盘点值
- 报废或丢失：数量减少并记录原因

每次操作都形成库存流水，包括变化前数量、变化量、变化后数量、时间和备注。

### 11.3 低库存提醒

- 当前数量低于或等于最低库存时触发。
- 相同库存状态不重复发送无意义的提醒。
- 用户补货后自动解除低库存状态。
- 可以一键将物品加入采购清单。

### 11.4 后续能力

- 多个存放位置
- 保质期和批次
- 购买日期与价格
- 保修期限
- 条形码扫描
- 购物小票识别

## 12. 智能创建

智能创建允许用户通过自然语言创建五种生活记录，可接入 GPT、千问等大模型。

### 12.1 产品定位

智能创建是创建记录的一种快捷方式，不是独立聊天模块。即使模型不可用，五种记录的手动创建功能仍应完整可用。

### 12.2 入口

用户点击全局加号后看到：

```text
想记录什么？

[ 告诉我你想创建的事项……                  ]

例如：每周日晚上九点提醒我整理下周计划

[语音输入]                         [帮我整理]

也可以手动创建：
重复事项  清单  备忘  重要日期  家庭物品
```

语音输入可以在后续版本开放，第一版优先支持文字。

### 12.3 创建流程

1. 用户输入自然语言。
2. 系统识别记录类型及字段。
3. 如果缺少影响创建的关键信息，系统提出一个简短问题。
4. 模型生成结构化草稿。
5. 程序执行字段和业务规则校验。
6. 系统展示用户可理解的确认单。
7. 用户修改、重新生成、取消或确认。
8. 只有用户确认后，记录才写入数据库。

### 12.4 输入示例

- “从明天开始，每隔两天晚上十点提醒我吃药，持续一个月。”
- “我十月三号去北京玩五天，帮我建一个旅行准备清单。”
- “记一下，客厅空调滤芯型号是 ABC-123，放在储物间第二层。”
- “结婚纪念日是每年十月二十日，提前三十天、七天和当天提醒。”
- “今天买了十二卷纸巾，原来还有四卷，少于六卷时提醒购买。”

### 12.5 追问原则

- 只询问会影响正确创建的关键信息。
- 一次优先只问一个问题。
- 可以安全采用默认值时不打断用户，但要在确认单中标记。
- 对日期、时间、数量和重复范围的歧义必须确认。

示例：

> 用户：下周提醒我买礼物。  
> 系统：你希望下周哪一天提醒？如果没有特别要求，可以设置为周一上午九点。

### 12.6 确认单

确认单展示正常产品字段，不直接展示模型返回的 JSON。

```text
确认创建内容

家庭物品
────────────────
名称        牙膏
现有数量    6 支
最低库存    2 支（系统建议）
存放位置    卫生间柜子
库存提醒    少于 2 支时提醒

[返回修改]                  [确认创建]
```

模型推断而非用户明确提供的内容，必须标记为“系统建议”或“根据描述推测”。

### 12.7 一次创建多条记录

后续版本支持从一句话生成多张草稿卡片。

例如：

> 下个月去云南旅行，帮我准备行李清单，出发前三天提醒检查证件，并记一下家里有两个行李箱。

系统可以生成：

1. 云南旅行准备清单
2. 出发前检查证件提醒
3. 行李箱家庭物品记录

用户可以逐条修改或取消，也可以全部确认。第一版默认一次只创建一条记录。

### 12.8 模型接入架构

系统使用统一的模型供应商接口，不把业务逻辑绑定到某一家模型：

```text
用户输入
   ↓
模型供应商适配器（GPT / 千问 / 其他）
   ↓
统一的结构化记录草稿
   ↓
程序校验
   ↓
用户确认
   ↓
保存到生活簿
```

不同供应商的返回结果必须转换成同一套内部草稿格式。切换模型不能影响已有数据和确认页面。

普通用户默认使用产品内置的智能创建服务，不需要配置供应商或 API Key。高级用户可以在后续版本中配置自己的 GPT、千问或兼容接口 Key。自带 Key 必须保存在操作系统提供的安全存储中。

内置服务可以设置免费使用额度，但额度用完不能影响手动创建。正式计费方式在商业模式确定后另行说明。

### 12.9 安全边界

- 大模型不能直接访问或写入数据库。
- 所有写入、修改和数量变化都必须先展示确认内容。
- 服务端必须校验模型输出，不能把模型结果视为可信数据。
- API Key 不得写入客户端安装包或提交到代码仓库。
- 默认只发送本次输入、当前日期、用户时区和必要的字段定义。
- 默认不发送用户的全部备忘、物品和日期记录。
- 如果需要读取已有记录，必须清楚说明使用了哪些数据。
- 敏感记录可以被标记为禁止用于任何智能功能。
- 错误日志和数据分析不得保存完整的用户输入或备忘正文。

智能功能读取已有数据按版本逐步开放：

- P0：仅使用本次输入和必要的时间上下文。
- P1：用户主动选择一条已有记录作为参考。
- P2：模型可以提出修改已有记录的草稿，但必须逐项确认。

### 12.10 异常处理

- 模型请求超时时允许重试。
- 无法识别记录类型时，引导用户选择一种手动类型。
- 返回字段不合法时，不进入保存流程。
- 模型服务不可用时，保留用户原始输入并打开对应手动表单。
- 不因模型失败丢失用户输入。

## 13. 提醒系统

### 13.1 提醒来源

- 重复事项
- 清单截止时间
- 备忘提醒
- 重要日期
- 低库存状态
- 后续的保质期和保修期

### 13.2 通用能力

- 指定日期和时间
- 提前若干分钟、小时或天
- 同一记录设置多次提醒
- 稍后提醒
- 从通知中直接完成或跳过
- 关闭某一条提醒
- 关闭某一类提醒
- 用户主动设置重复催促及间隔

### 13.3 可靠性规则

- 到达设定时间时默认只发送一次系统通知。
- 未处理的提醒在“今天”页面持续显示为逾期，默认不连续推送。
- 重复事项的每个周期相互独立，本次逾期不阻止下一次生成。
- 低库存只在首次进入不足状态时提醒，补货恢复后再次不足才重新提醒。
- 所有相对日期都以用户当前时区计算。
- 用户更换时区后，区分“保持本地时间”和“保持绝对时刻”的场景。
- 相同事件避免重复通知。
- 用户拒绝通知权限时，应用内仍显示提醒状态并解释如何重新开启。
- 离线期间能够由本地通知完成的提醒不应依赖实时联网。
- 用户明确设置的准确提醒时间不被应用勿扰规则擅自修改。
- 系统建议和回顾等非用户明确设置的通知遵守应用勿扰时段。

## 15. 数据、隐私与备份

### 15.1 基本原则

- 生活数据默认私密。
- 数据保存在应用私有目录。
- 明确区分本地数据、云端同步数据和发送给模型的数据。
- 用户可以导出自己的数据。
- 删除账号或空间时提供清楚的数据处理说明。
- 用户可以使用 Face ID、指纹或设备密码锁定应用。
- 单条记录可以标记为敏感内容或禁止用于智能功能。
- 用户可以设置系统通知显示完整内容、只显示标题或完全隐藏。
- 敏感记录的系统通知默认不显示标题和正文。
- API Key 使用操作系统安全存储，不进入普通数据库、日志或代码仓库。

### 15.2 备份与导出

P0 必须同时提供备份和恢复能力：

- 创建加密备份文件
- 从加密备份恢复全部数据
- 导出 JSON 或其他结构化格式
- 导出可阅读格式，并明确提示导出文件未加密

删除的记录默认进入回收站并保留 30 天。永久删除、清空回收站和删除整个空间需要二次确认。

P1 增加加密云备份和跨设备同步。端到端加密的具体范围在同步与家庭共享架构确定后评估，不在 P0 提前承诺。

### 15.3 家庭共享预留

虽然第一版以个人使用为主，数据结构应预留“空间”概念：

- 个人空间
- 家庭空间
- 记录所属空间
- 记录创建人和最后修改人

后续再增加查看、编辑和管理等成员权限。

## 17. P0 验收基线

首个版本至少满足以下完整流程：

1. 用户可以不用大模型，手动创建五种记录。
2. 用户可以点击加号，用一句自然语言生成一条草稿。
3. 草稿能够正确展示类型、日期、重复规则、提醒或数量等关键字段。
4. 用户可以在确认前修改或取消，未经确认不会产生记录。
5. 创建成功后，记录出现在正确的列表和今天页面中。
6. 到达提醒时间时，用户能够收到一次正确且不重复的提醒。
7. 重复事项的一次完成或跳过不会破坏后续周期。
8. 从模板生成的清单不会修改原模板。
9. 物品每次增减都能查看库存流水，当前数量计算正确。
10. 模型服务失败时，用户输入不会丢失，并可以继续手动创建。
11. 没有网络时，除智能创建外的核心功能仍然可用。
12. 应用锁和敏感通知按用户设置生效。
13. 用户可以创建加密备份，并在清除本地数据后成功恢复。
